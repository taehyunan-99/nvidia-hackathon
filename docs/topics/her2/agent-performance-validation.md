## 결론

**`diffusion_samples=1`이 병목이라는 결론은 현재 근거로 성립하지 않는다.**
동일한 서비스 입력 순서로 새로 측정한 트라스투주맙은 1개와 5개 모두 F1 0.884였고,
퍼투주맙에서는 신뢰도로 5개 중 고르는 방법이 더 나빴다. 기본 생성 수는 1개를 유지한다.

확인된 결함은 mmCIF 파싱, 저장 오류 뒤 중복 예측, 불필요한 입력 검사 모델 호출,
그리고 의견 제출 뒤 생긴 오류를 측정기가 놓치는 문제다. 아래 수정은 모두 로컬 검증을 통과했다.

## 실제 구조 예측 비교

새 Boltz-2 호출은 총 **4회**, 모두 HTTP 200. 동일한 API·서열·사슬 순서(A=표적, H=중쇄, L=경쇄),
recycling_steps=3, sampling_steps=50으로 생성 수만 비교했다. 설정별 1회이며 독립 seed 반복은 아니다.
점수는 실험 구조의 표적쪽 4.5 Å 접촉 잔기 집합에 대한 F1이다. 1S78은 첫 복합체 한 벌만 사용한다.

| 입력 | 1개 생성 F1 | 5개 중 신뢰도 선택 F1 | 5개 중 사후 최고 F1 | HTTP 시간(1개/5개) |
|---|---:|---:|---:|---:|
| 1N8Z 트라스투주맙 | 0.884 | 0.884 | 0.884 | 27.28 / 16.31초 |
| 1S78 퍼투주맙 | 0.041 | 0.000 | 0.286 | 11.13 / 14.23초 |

사후 최고 F1은 정답을 아는 평가자가 고른 값이다. 서비스가 고를 수 있는 성능으로 제시하지 않는다.
퍼투주맙에서 신뢰도 최대는 응답 인덱스 2, F1 최대는 인덱스 3으로 **서로 달랐다**.
시간은 단일 호출 관측치이므로 5개 생성이 더 빠르다는 근거도 아니다.

원본은 `work/quality/<PDB>-<samples>/boltz2_response.json`에 캐시했다. 요약과 서열·응답·실험 구조 SHA256은
[generated/verified-*.json](assets/goldset/generated/)에 있다. 실험 구조는 기존 저장소의 RCSB 스냅샷이며,
JSON의 `verified_at`은 이번 검증 시각이지 RCSB 다운로드 시각이 아니다.
구조별 confidence_scores가 대응한다는 API 계약은 [NVIDIA 공식 문서](https://docs.nvidia.com/nim/bionemo/boltz2/1.8.0/inference.html)를 확인했다.

## 기존 결론 정정

1. **원자 0개와 접촉 0개는 다르다.** 기존 줄 단위 파서는 실제 받은 1S78 1샘플의 중원자
   8,149개를 0개로 읽었다. gemmi로 읽으면 표적 접촉 23개, 적중 1개, F1 0.041이다.
   실제 응답에 대한 구·신 파서 비교는 [parser-replay.json](assets/goldset/generated/parser-replay.json).
2. **OpenFold3가 복합체를 못 만들었다는 주장은 철회한다.** 저장본은 7,969개의 중원자를
   읽을 수 있고 표적 접촉 21개 중 2개가 맞는다(F1 0.100). 기존 0은 파싱 문제였다.
   이 값은 of3-crosscheck 원래 기록의 표적쪽 2/19와 일치한다.
3. **세션이 원인이라는 인과 결론은 미확인이다.** 저장본은 중쇄·경쇄·표적 순서(A/B/C),
   sweep과 서비스는 표적·중쇄·경쇄 순서(A/H/L)여서 요청 자체가 다르다.
   같은 SHA256의 3회 반복은 관측 사실이지만 결정론 보장이나 독립 표본 3개를 뜻하지 않는다.
4. **기존 sweep 응답 JSON은 재채점 원본이 아니다.** 구조 문자열이 `<785544 chars>` 같은
   요약으로 대체돼 있었다. 이전 1샘플 F1 0.0의 정확한 원인은 원본 유실 때문에 확정할 수 없다.
   이번 평가기는 원본을 보존하고, 파싱 불가를 0점으로 세지 않는다.
5. **0.923은 상한이 아니다.** 6BGT와 1N8Z의 실험 구조 사이 유사도 관측값이다.
6. Boltz-2+MSA 저장본은 재계산해도 0/19다. 이 입력에서는 이점이 없지만 다른 항체의
   MSA 성능까지 일반화하지 않는다.

## 적용한 변경

- `logic/contacts.py`: 직접 줄을 쪼개던 코드를 설치된 gemmi CIF 파서로 교체. label 사슬·잔기,
  모델 번호, 수소 제외, 4.5 Å 기준은 보존한다. 새 의존성은 없다.
- `logic/flow.py`: 여러 구조가 반환되면 유효 신뢰도 최댓값의 구조와 **같은 인덱스의 점수**를
  기록한다. 빈 구조는 제외하고, 점수 배열 길이 불일치·NaN·무한대·bool·범위 밖 값은 신뢰도 미상으로
  처리한다. 유효 점수가 없으면 첫 유효 구조를 사용했다고 명시한다. 기본 요청 수는 1개다.
- 기존 `c520bb3`의 M1 수정 재사용: 예측 뒤 기록이 실패하면 부분 기록을 되돌리고 후보를 실패로
  끝내서 재호출을 막는다. M2의 도구 호출 수 기반 반복 상한 추정은 이번 변경에 가져오지 않았다.
- `logic/nat_agent.py`: 결정론적 입력 검사를 먼저 수행한다. 정상 입력은 조회부터 모델이 진행하며,
  잘못된 입력은 모델을 전혀 부르지 않는다. 검사 기록은 `executed_by=code`로 구분한다.
- `logic/measure_agent.py`: 선택한 의견뿐 아니라 모든 후보의 모델 오류를 확인한다. 의견 제출
  이후 또는 filler에서 발생한 429도 남기고, 코드가 실행한 도구 수를 별도로 기록한다.
- 미계산 항목이 남거나 측정 근거가 없으면 `reviewable`을 허용하지 않는다. NAT는 제출을 거부해
  `needs_confirmation`으로 수정하도록 안내하고, 일반 판단 경로도 같은 선택 제약을 사용한다.
  기존 보수적 규칙 기본값을 모델에도 적용한 **제품 판단 제약 변경**이며 생물학적 정확도 기준은 아니다.

[실측 기록](assets/goldset/generated/agent-performance-live.json), 원문 로그는 `work/*live*.log`.

설명을 낸 것도 확인했다. 그 뒤 위 판단 제약과 프롬프트를 추가했다. 해당 조건의 `reviewable`
제출이 거부되고 보완 의견은 정상 제출되는 것을 결정론 테스트로 확인했다. 일반 판단 경로도 검증했다.
이 시점에는 마지막 제약의 실모델 재측정을 하지 못했다. 아래 후속 검증에서 두 사례의
제약 준수를 확인했다. 미계산 항목의 실제 배선과 자유 문장 전체의 사실성 검증은 남은 한계이며,
모델 정확도 개선률을 주장하지 않는다.

## 샘플 간 에피토프 일치도 — 지표로 쓸 수 없다 (2026-09-27)

8JYR의 실패 원인을 항체 CDR 위치로는 못 가렸다. 그래서 정답을 몰라도 잴 수 있는
신호를 찾아 **샘플 간 에피토프 일치도**를 시험했다. 같은 입력으로 나온 구조들이
서로 다른 자리에 붙으면 그 예측을 의심하자는 가설이었다.

**가설은 틀렸다.** 맞은 사례와 틀린 사례가 갈리지 않는다.

| 사례 | 후보=트라스투주맙 | 평균 짝 일치도 | 최대 | 모든 샘플 공통 잔기 |
|---|---|---:|---:|---:|
| 1N8Z (맞음) | 예 | 0.050 | 0.500 | 0개 |
| 1S78 (틀림) | 아니오 | 0.005 | 0.027 | 0개 |

둘 다 바닥이라 임계값을 그을 자리가 없다. 지표 후보에서 내린다.

재는 과정에서 나온 사실은 남긴다.

- **5개 샘플은 서로 완전히 다른 자리에 붙는다.** 1N8Z에서 신뢰도 1위는 실험
  에피토프 19개를 19개 모두 복원했는데, 나머지 4개는 복원 0개였고 접촉 자리가
  도메인 I·II 쪽(잔기 11~241, 101~104 등)으로 흩어졌다. 모든 샘플에 공통인 잔기는
  두 사례 다 0개다. 예측이 붙을 자리를 정하지 못한다는 뜻이다.
- **신뢰도 순위는 에피토프 정확도를 따라가지 않는다.** 1N8Z는 1위가 정답이었지만,
  1S78은 1위(`model_0`, conf 0.8221)가 실험 에피토프와 겹침 0이고, 실험에 제일
  가까운 샘플은 4위(`model_2`, conf 0.7933, 26개 중 7개 복원)였다. 사례 2건이라
  규칙으로 세우지 않고 관측으로 적는다.
- **샘플을 늘리면 다른 틀린 답이 뽑힐 수 있다.** 1N8Z는 1샘플 실행과 5샘플의
  선택이 같은 구조였지만, 1S78은 달랐다. 1샘플 실행은 트라스투주맙 계면
  (잔기 555~593)을 재현했고, 5샘플에서는 그것이 2위로 밀리고 잔기 141~196에
  붙은 `model_0`이 뽑혔다. `diffusion_samples`를 올려도 정확도가 오르지 않는다는
  기존 결론과 같은 방향이다.

측정은 캐시된 응답만 썼고 **새 API 호출은 0회**다. 5샘플 응답이 있는 사례가
1N8Z·1S78뿐이라 **8JYR·3N85는 이 지표를 재지 못했다.** 8JYR의 겹침 0 원인은
여전히 미해결이다. 산출물은
[샘플 간 일치도 측정 결과](assets/goldset/generated/sample-agreement-check.json)다.

## 재실행

저장소 루트에서 실행한다. 캐시가 있으면 새 API 호출은 없다.

```sh
python -m pytest -q
python docs/topics/her2/assets/goldset/verify_prediction.py --case 1N8Z --samples 1
python docs/topics/her2/assets/goldset/verify_prediction.py --case 1N8Z --samples 5
python docs/topics/her2/assets/goldset/verify_prediction.py --case 1S78 --samples 1
python docs/topics/her2/assets/goldset/verify_prediction.py --case 1S78 --samples 5
python docs/topics/her2/assets/goldset/score_saved_predictions.py
python docs/topics/her2/assets/goldset/check_sample_agreement.py
git diff --check
```

신규 호출은 평가기에 `--fetch --env /path/to/.env`를 명시해야 한다. 429 자동 재시도는 하지 않는다.
이번 검증은 구조 접촉과 실행 신뢰성에 한정한다. 실험 결합력·치료 효능·변이 결합 저하 탐지의
정확도를 검증한 결과가 아니며, 두 항체를 넘는 일반화도 미확인이다.
