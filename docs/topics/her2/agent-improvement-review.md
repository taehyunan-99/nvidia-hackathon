# 에이전트 개선 검토와 측정

검토일: 2026-09-27. 기준 HEAD `1c15305`와 이전 출처 재사용 작업의 미커밋 변경을 포함한 작업 트리. 이전 변경을 보존한 `feat/structure-source-reuse`에서 진행했다. 사용자 요청은 개선 가능성을 상세히 검토하되 효과 없는 시도를 오래 반복하지 않는 것이다. NVIDIA 실호출은 승인된 범위 밖이어서 0회로 유지했다.

## 판단

**자료 확보와 검토 의견의 유용성에는 확인 가능한 개선 여지가 있었다. 새 항체의 구조 예측 정확도를 높이는 방법은 이번 조건에서 입증하지 못했다.** 두 문제를 같은 성능 점수로 합치지 않는다. 테스트 통과 수, 구조 파일 생성, 자기 신뢰도는 실제 결합·효능이나 예측 정확도가 아니다.

## 1. 변경 전 상태와 비교 방법

수정 전에 기존 10개 오프라인 사례를 실행하고 관련 소스·해시를 `tmp/performance-review/baseline-source/`와 `baseline-manifest.json`에 보존했다. 같은 입력을 수정 후 다시 실행했다. 실제 모델 대신 규칙 판단과 통제된 오류/응답을 사용했으며 HTTP 실패를 생물학적 실패로 채점하지 않았다.

기존 `hackathon-v1` 데이터·20점 기준을 이번 점수에 맞춰 바꾸지 않았다. 아래 항목 가용성 측정은 [주제별 판정 기준](hackathon-evaluation.md#2-판정-단위는-주제별)에 근거한 별도 관찰이며, 내부 20점이나 모델 정답률과 혼합하지 않는다. 계산값·단위를 그대로 유지했는지도 비교했다.

## 2. 항목별 판단의 의미

접촉, 단백질 표면, 관측 당의 표면 영향, 충돌, 전체 접근성, 모델 신뢰도 기록을 분리한다. 표면은 해당 조건의 표면적·매몰 면적이 함께 있어야 하고, 관측 당 항목은 같은 조건의 표면적·감소량이 함께 있어야 한다. 일부 항목만 측정됐거나 같은 항목의 근거가 중복/모순되면 그 항목을 추가 확인으로 남긴다.

`reviewable`은 **선택한 좌표에서 얻은 해당 계산 근거를 검토할 수 있다**는 뜻이다. 실험 우선순위·결합력·치료 효능·예측 정확도를 승인하는 뜻이 아니다. 화면 문구도 ‘해당 항목 검토 가능’으로 바꿨다. 측정된 0은 검토할 수 있는 관측값으로 유지하고, 미계산 항목을 0으로 채우지 않는다.

의견은 같은 후보·조건·구조의 근거만 연결한다. 빠진 항목도 해당 의견과 연결해 다른 주제의 의견이 대신 표시되지 않게 한다. 자유로운 모델 설명은 결과의 과학적 사실로 저장하지 않으며, 출처·값·단위는 기존 Evidence를 그대로 소비한다. 중복·다른 후보·조건·구조를 섞은 입력은 회귀 검사로 확인한다.

모델의 진행 선택과 항목별 코드 판정을 구분한다. `measure_agent.py`는 보고 문구에 ‘규칙’이 있다는 이유로 모델 실패를 추정하지 않고 실제 규칙 재개 기록으로 집계한다. 의견 제출 뒤 오류가 나더라도 이미 끝난 후보를 규칙 복구로 세지 않는다. 측정 행에는 주제별 판정도 남기며 첫 접촉 의견을 후보 전체 승인으로 사용하지 않는다.

## 3. 자동 검색의 효과와 제한

[RCSB 공식 Search API](https://search.rcsb.org/)의 단백질 서열 검색을 사용한다. 서버가 중쇄 검색 후보를 반환해도 그것만으로 일치 구조라고 하지 않는다. 받아온 실험 mmCIF의 전체 중쇄·경쇄, HER2 607잔기 구간, 실제 사슬·좌표·파일 해시를 다시 검증한다.

실제 공개 검색의 작은 사전 시험에서 39S는 6ATT 한 건, Fab37은 3N85 한 건, 가상 D31A는 결과 없음이었다. Trastuzumab 검색에는 20건이 나왔으므로 검색 점수 1.0을 유일한 전체 복합체 일치로 해석할 수 없다. 이미 검증한 로컬 정확 일치가 있으면 검색 요청 자체를 생략한다. 처음 시도한 길이 필터 속성은 API가 HTTP 400으로 거부해 제거했으며, 성공한 최종 조회 형태만 제품에 반영했다.

검색은 중쇄 identity cutoff 1.0의 후보 수집이며 전 세계 구조의 부재를 증명하지 않는다. 네 개 이하의 완전한 결과만 내려받고, 더 많거나 복수의 완전 일치가 있으면 번호를 지정하도록 한다. 일치하지 않는 다른 표적의 검색 후보는 제외하지만, 조회 장애·응답 손상·구조 무결성 실패를 정상적인 ‘검색 결과 없음’으로 바꾸지 않는다. 임의 유사 서열의 구조를 변이체에 붙이지 않는다.

검색 query·HTTP 상태·응답을 실행 폴더에 기록한다. `PDB_SEARCH_ENABLED=0`이면 자동 검색을 비활성화하고 로컬 목록과 명시적 출처만 사용하며, 테스트 기본값도 0이다. 자동 검색 검사에서는 이를 명시적으로 켜고 대역·실제 공개 검색을 구분한다. NVIDIA 호출 허용 설정과는 별개다.

## 4. 예측 정확도에 대한 냉정한 판단

[저장소의 기존 실측](agent-performance-validation.md#실제-구조-예측-비교)은 생성 수 1→5에서 Trastuzumab 접촉 F1이 0.884→0.884, Pertuzumab은 신뢰도 선택 시 0.041→0.000이었다. 설정별 1회이며 독립 seed 반복이 아니므로 보편적인 효과 없음도, 개선 상한도 증명하지 않는다. 다만 **지금 같은 설정으로 더 생성하면 좋아진다고 가정할 근거가 없다.** 정답을 보고 고른 사후 최고는 실제 서비스가 선택할 수 있는 성능이 아니다.

그 실험의 요약 JSON은 현재 저장소에서 확인했지만 기록된 외부 디스크의 원본 5샘플 경로는 현재 사용할 수 없었다. 따라서 이번에는 새로운 자세 점수나 재선택 정확도를 독립 재계산했다고 주장하지 않는다. 단순 가중치 탐색으로 이 개발 사례에 맞춘 점수만 올리는 시도는 하지 않았다.

조사 결과도 같은 구분을 요구한다.

- [Boltz-2 원 논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC12262699/)은 복잡한 상호작용·큰 구조 변화의 한계를 명시한다. 논문의 단백질–소분자 친화도 성과를 HER2–항체 친화도 성능으로 전용하지 않는다.
- [519개 치료용 항체를 다룬 2026년 사전공개 연구](https://www.biorxiv.org/content/10.64898/2026.05.13.724924v1)는 올바른 표적/무작위 표적 구분에서 신뢰도 지표의 약한 분별력과 제한된 추가 모델링 효과를 보고했다. 초록에서 확인한 결과이며, HER2 자세 정확도와 같은 과제가 아니다.
- [106개 나노바디 복합체와 비대응 조합을 다룬 사전공개 연구](https://www.biorxiv.org/content/10.64898/2026.03.02.709004v1)는 구조적으로 그럴듯함과 결합 특이성을 구별한다. 항체 형식·자료 구성이 달라 그 수치를 현재 Fab 데모에 그대로 적용하지 않는다.
- [DockQ](https://github.com/wallnerlab/DockQ)는 실험 기준 구조와의 자세 평가에 유용하지만, 정답이 없는 새 후보의 실행 중 선택 점수로 바로 사용할 수 없다. 평가 도구를 추가하는 것 자체도 예측 성능 향상이 아니다.

템플릿·제약은 영구적으로 불가능하다고 판단하지 않는다. [NIM 1.8 추론 문서](https://docs.nvidia.com/nim/bionemo/boltz2/1.8.0/inference.html)는 structural templates를 설명하고 [호스팅 API 문서](https://docs.api.nvidia.com/nim/reference/mit-boltz2-infer)는 MSA·constraints·생성 설정을 공개한다. 그러나 현재 계정의 endpoint가 원하는 템플릿 형태를 실제로 받는지, 정답 계면을 유출하지 않고 개선하는지는 확인하지 않았다. 이번에는 그 검증 없이 요청 필드를 추가하거나 모델을 바꾸지 않았다.

## 5. 재개 조건과 실행 증거

새 예측 정확도 실험은 아래 조건이 있어야 가치가 있다.

1. 원본 예측 파일과 같은 후보·construct의 실험 기준을 확보하고, 개발에 사용하지 않은 구조군을 별도로 정한다.
2. endpoint 지원·호출 예산을 확인한 한 가지 가설만 비교한다. 샘플 수·입력 구간·템플릿·순위 규칙을 한꺼번에 바꾸지 않는다.
3. 시도 전체를 분모에 남기고, 구조 획득 성공·모델 선택·접촉/자세 정확도·시간을 따로 측정한다. 개발 자료에서만 개선되거나 독립 비교에서 이득이 반복되지 않으면 채택하지 않는다.

이번 개인 근거는 Git 제외 `tmp/performance-review/`에 있다: `topic-comparison.json`, `retrieval-comparison.json`, `report-call-counts.json`, `baseline-v1/`, `after-v1/`, `search-spike/`, `retrieval-comparison/`, 테스트 로그와 화면 캡처. NVIDIA 실호출 0회이며 공개 RCSB 조회는 실제 실행했다. 브라우저·worker 검증에는 그 응답을 고정한 오프라인 대역을 사용한다. 공개 배포·커밋·push는 하지 않는다.

### 최종 검증

- 새 폐기용 PostgreSQL DB에서 **291 passed, 2 skipped**. 생략은 별도 조건이 필요한 실제 모델 검사이며 성공으로 세지 않는다. 초기 회귀에서 발견한 규칙 재개 사유 누락과 측정기의 ‘문구로 모델 실패 추정’도 수정했다.
- 프런트 상태 검사 **8 passed**, 저장형 설정의 타입·빌드, 계약의 정상 9개/오류 9개 검사 통과. 배포용 빌드의 큰 청크 경고는 남아 있으며 성능 측정 없이 번들 최적화까지 확대하지 않았다.
- 브라우저 직접 입력→실제 worker/분석 subprocess→저장·새로고침→후보별 3D·보고·파일 해시 확인: 공개 원본 두 후보 completed, 번호 없는 익명 39S·Fab37 completed, 원본+가상 변이 partial. 마지막 사례의 변이만 NVIDIA 키 부재로 보류됐다.
