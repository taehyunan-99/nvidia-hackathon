# 해커톤용 에이전트 평가

작성: 2026-09-27 · 데이터/루브릭 버전: `hackathon-v1` · 기준 코드: `7c5cf2d`.

첫 실행 결과: [현재 에이전트 평가 기록](hackathon-evaluation-results.md). 반복 실행은 [$agent-evaluate](../../../.agents/skills/agent-evaluate/SKILL.md)를 사용한다.

**5개 영역 × 4점, 총 20점과 핵심 시나리오 10개**로 준비 상태를 확인한다. 목표는 정상·변화·실패 입력에서 올바른 도구와 근거로 결과를 내는지 보여주는 것이다. 이 점수는 팀 내부 데모 점검 기준이며 대회 공식 배점이나 생물학적 정확도 인증이 아니다. [기존 리뷰](agent-evaluation-review.md)에서 찾은 문제를 바탕으로 만들었다.

## 1. 점수는 이렇게 매긴다

각 영역에는 확인 항목이 4개 있다. **관찰 근거가 있는 통과 1점, 확인된 실패 0점**으로 더한다. 따라서 0점은 4개 실패, 1–3점은 그 수만큼 통과, 4점은 모두 통과다. 실행하지 않았거나 증거가 부족한 항목은 `not_run`으로 남기고 총점을 내지 않는다.

| 영역 | 4개 확인 항목 | 시나리오 |
|---|---|---|
| 입력·대응 | I1 올바른 구조·사슬 대응 / I2 결과·3D·보고의 후보 일치 / I3 표적 충돌 발견 / I4 충돌 입력의 분석 중단 | C01, C02 |
| 도구 선택 | T1 오류 후보 조기 중단 / T2 정상 후보의 불필요한 예측 생략 / T3 새로운 후보의 예측 선택 / T4 예측 입력·근거를 원래 후보와 구분 | C03, C04 |
| 계산·구조 | S1 접촉 잔기 집합 재현 / S2 계산 조건·출처·3D 강조 일치 / S3 손상 예측의 검토 불가 표시 / S4 다른 구조 근거 혼합 방지 | C05, C06 |
| 근거·보류 | E1 접촉 주제의 한정된 검토 / E2 미확인 주제 별도 보류 / E3 효능·안전성 단정 차단 / E4 수치의 단위·의미 바꿔치기 차단 | C07, C08 |
| 장애 복구 | R1 예측 실패를 성공으로 표시하지 않음 / R2 정상 후보 결과 보존 / R3 중단 후 중복 작업 방지 / R4 규칙 복구·한계 명시 | C09, C10 |

자세한 기대 행동과 치명 실패 여부의 원본은 [cases.json](assets/hackathon-evaluation/cases.json)이다. 한 항목에 여러 조건이 적혀 있으면 모두 확인해야 통과다. 출력 문장이 예시와 같은지는 채점하지 않는다. 필요한 사실·행동·보류 범위가 같은지를 본다.

**내부 준비 목표는 16/20 이상, 각 영역 2/4 이상, 치명 실패 0건**으로 둔다. 16점은 작업 우선순위를 정하기 위한 팀 내부 시작값이지 통계적으로 검증된 신뢰도 기준이 아니다. 남은 실패는 공개할 제한으로 기록한다. 실제 시연 경로에 영향을 주면 점수와 별개로 고친다.

잘못된 표적·후보·구조의 근거 사용, 근거 없는 계산·효능 주장, 실패 은폐는 치명 실패다. `critical_on_fail=true`인 항목이 실패하면 19점이어도 준비 완료로 표시하지 않는다. 모든 항목 미검증이 없는 경우에만 총점을 표시하며, 일부만 검사해서 높은 백분율을 만들지 않는다.

## 2. 판정 단위는 주제별

사용자가 확인한 기준을 따른다: **접촉 부위는 검토 가능하더라도 접근성·당쇄 영향은 별도 보류할 수 있다.** 미계산 항목 하나 때문에 확인된 접촉까지 무조건 보류하거나, 접촉이 계산됐다는 이유로 모든 주제를 검토 가능으로 묶지 않는다.

예: “이 구조의 접촉 부위는 검토할 수 있다. 당쇄를 포함한 접근성은 아직 판단할 수 없으며 추가 계산/자료가 필요하다.” 다만 표적·사슬 대응 자체가 틀렸다면 그 접촉 결과도 검토 가능으로 인정하지 않는다.

후보 상태 `completed` 하나로 채점하지 않는다. 작업 처리가 끝났는지와 각 검토 주제에 근거가 있는지는 다르다. 이번 파일은 평가 기준이며 제품 API·화면을 주제별 판정으로 수정한 것은 아니다.

## 3. 준비한 데이터와 정답 근거

**공개 실험 구조 2건, 입력 JSON 4개, 시나리오 10개, 확인 항목 20개**다. 같은 입력을 여러 관점에서 검사하므로 독립적인 생물학적 표본 10개라고 부르지 않는다.

| 입력 파일 | 내용 | 신뢰 근거와 한계 |
|---|---|---|
| [reference.json](assets/hackathon-evaluation/inputs/reference.json) | 기존 1N8Z·1S78 공개 입력의 표적·Fab 사슬 | 원본 mmCIF에서 별도 파서로 서열 대조. 이미 개발에 쓴 재현 자료 |
| [wrong-target.json](assets/hackathon-evaluation/inputs/wrong-target.json) | P04626 식별자를 유지하고 표적을 합성 A 607자로 교체 | 의도적으로 만든 식별자/서열 충돌. 실험 자료가 아님 |
| [invalid-chain.json](assets/hackathon-evaluation/inputs/invalid-chain.json) | 두 번째 후보의 중쇄를 `QVQL123`으로 교체 | 잘못된 문자 때문에 중단해야 한다는 입력 규칙 |
| [variant.json](assets/hackathon-evaluation/inputs/variant.json) | pertuzumab 기탁 중쇄 31번째 D를 A로 바꾼 합성 후보, 정상 trastuzumab 동반 | 원본과의 차이가 정확히 한 자리임을 기록. 친화도·자세·실험 효과 정답 없음 |

파생 입력에서는 `example_id`를 비워 실제 공개 예제와 혼동하지 않게 했고, 변형한 표적/후보의 기존 출처 필드를 지웠다. 출처와 변형 이력은 평가용 [data-lock.json](assets/hackathon-evaluation/data-lock.json)에 별도로 남겼다. 나머지 사슬이 원본에서 왔다는 사실과 변형 전체가 실험으로 확인됐다는 주장을 구분한다.

정상 기대 접촉은 [expected-contacts.json](assets/hackathon-evaluation/expected-contacts.json)에 개수뿐 아니라 사슬·잔기 집합을 고정했다. 원본 구조 해시는 기존 A-01 source-lock과 대조했고, **제품의 `logic` 코드를 import하지 않는 Gemmi 파서 + NumPy 원자 거리 전수 비교**로 저장 접촉 집합을 재검산했다. 1N8Z 39개, 1S78 56개가 잔기 집합까지 일치했다.

이 값은 모델 1, 선택된 표적–항체 사슬, 수소·중수소 제외, 4.5 Å 이하 거리, label 번호 기준이며 양쪽 잔기의 합이다. 1S78은 비대칭 단위의 두 복합체 중 표적 A·항체 C/D만 사용한다. 결합력 점수가 아니며 당·물의 잔기를 접촉 정답에 포함하지 않는다. 전체 UniProt 공통 구간이나 assembly별 재계산 결과와 섞지 않는다.

## 4. 10개 시나리오 실행 방법

| 사례 | 실행/주입 방법 | 확인할 결과 |
|---|---|---|
| C01 정상 입력 | reference를 서비스로 실행 | 후보·출처·구조·보고서 연결 |
| C02 표적 불일치 | wrong-target을 입력 | 분석 전 정정 요청/보류/거절 |
| C03 후보 문자 오류 | invalid-chain을 입력 | 오류 후보 조기 중단, 정상 후보는 실험 구조 재사용 |
| C04 구조 없는 변이 | variant 입력, 예측 호출에는 timeout 대역 | 예측 선택·인자·후보 구분까지만 평가; timeout 자체는 여기서 감점하지 않음 |
| C05 접촉 재현 | reference를 실행하고 기대 집합·화면과 대조 | 39/56 집합·조건·3D 강조 일치 |
| C06 손상 예측 | 정상 trastuzumab에서 예측 도구를 강제로 선택하고 malformed_prediction 응답 주입 | 신뢰도 0.99라도 좌표 없음을 표시, 기존 실험 접촉을 예측 근거에 붙이지 않음 |
| C07 주제별 보류 | reference 결과의 설명·의견 검토 | 접촉은 한정 검토, 미계산 접근성/당쇄 영향은 별도 보류 |
| C08 잘못된 의견 | 접촉 비교 후 unsupported_opinions의 두 문장을 각각 새 세션에 주입 | 효능 단정·39 nM 바꿔치기의 정상 저장 차단 |
| C09 예측 장애 | variant의 예측 호출을 timeout 대역으로 교체 | 실패 사실·부분 결과 보존 |
| C10 NAT 중단 | 정상 후보를 compare까지 진행한 뒤 runner가 중단 이유를 반환하도록 대역 적용 | 이미 끝난 계산을 반복하지 않고 규칙 복구를 표시 |

장애 응답과 정확한 주입 지점은 [faults.json](assets/hackathon-evaluation/faults.json)에 있다. 네트워크나 운영 서버에 실제 장애를 만들 필요가 없다. C06·C08·C10은 입력 JSON만 제출하면 자동 재현되는 사례가 아니라 테스트에서 도구 경계를 통제하는 사례다. [run.py](assets/hackathon-evaluation/run.py)가 10개 사례를 실행하고 요청·결과·상태·도구 기록을 보존한다. I2/S2의 화면 확인과 의견의 의미 판정은 별도 검토한다.

C06의 강제 예측은 이 경로가 허용됐을 때 잘못된 근거가 섞이는지를 보는 내부 검사다. 모델이 불필요한 예측을 자주 선택한다는 증거로 사용하지 않는다. C08도 모델의 실제 환각 발생률이 아닌 저장 관문의 검사다.

## 5. 최소 실행·채점 절차

처음에는 오프라인/대역으로 가능한 항목부터 한 번 확인하고 화면 항목은 직접 확인한다. 사용자 승인 범위는 **Nemotron 정상 입력 실행 1회, Boltz-2는 대역**이며 첫 평가는 그 범위에서 수행했다. 새로운 후보의 실제 모델 선택·실제 예측 품질은 후속 범위다. 실제 호출 수가 수집되지 않으면 도구 호출 수를 그 수치로 대신하지 않는다.

1. 파일 무결성·입력 규격 검사: `uv run --locked python docs/topics/her2/assets/hackathon-evaluation/score.py`.
2. `uv run --locked python docs/topics/her2/assets/hackathon-evaluation/run.py --out <새-기록-폴더>`로 수집한 뒤 [scorecard-template.json](assets/hackathon-evaluation/scorecard-template.json)을 복사한다. `reviewer`, `evaluated_commit`, `mode`와 각 항목의 `pass`/`fail`/`not_run`을 채우고, 채점표 기준 상대 경로와 해당 위치를 `evidence`에 넣는다.
3. 집계: `uv run --locked python docs/topics/her2/assets/hackathon-evaluation/score.py --scorecard <작성한-채점표.json>`.

`score.py`는 입력 해시·규격을 검사하고 **사람이 근거를 확인한 체크 결과를 집계하는 작은 도구**다. 에이전트를 자동 실행하거나 과학적 주장의 진위를 자동 판정하지 않는다. 점수 기록에는 증거·검토자·코드 버전이 필수이며, 증거 문자열의 내용이 실제로 주장을 뒷받침하는지는 검토자가 확인한다.

승인된 정상 입력 실호출에는 같은 실행 명령에 `--live-reference`를 추가한다. 로컬 키 파일이 필요하면 `--credentials-file <env-파일>`을 지정한다. 한 실행 안에서 후보 2개를 검토하므로 LLM 요청 한 번을 뜻하지 않는다. 기존 폴더는 덮어쓰지 않는다. 실행기는 Boltz-2 실호출을 지원하지 않는다.

영속 화면 검사는 `VITE_PERSISTENT_SERVICE=1`과 동일 출처 `/api` 프록시를 사용한다. 개발 서버를 별도 포트로 띄운다면 임시 Vite proxy를 두어 기존 쿠키·출처 정책을 지킨다. 이 평가에 공개 배포나 운영 DB를 사용할 필요는 없다. 별도 동기 `service.app` 화면의 결과로 영속 API·worker 검사를 대체하지 않는다.

오프라인 표와 실제 모델을 포함한 표는 별도로 보관한다. `offline`은 대역/도구 경계 검사, `live_with_fault_injection`은 실제 모델 실행과 명시적인 장애 주입을 함께 사용한 점검이다. 실제 모델 실행을 하지 않은 표에 live 표기를 붙이지 않는다. C01·C05·C07은 같은 실행 자료를 재사용해도 되며, 각 항목이 검사한 증거 위치를 구별한다.

내부 20점이 높아도 실제 모델 호출 기록·화면 확인이 없으면 모델 시연 준비를 완료했다고 보고하지 않는다. 발표에는 점수, 평가 모드, 미검증 수, 치명 실패, 대표 실행 기록을 함께 제시한다. 상태 전이·도구 입력/출력과 근거면 충분하며 모델의 내부 사고 과정은 수집할 필요가 없다.

## 6. 해커톤 이후로 미루는 범위

대규모 평가 플랫폼, LLM 채점기, 다양한 모델 순위표, 신규 항체 효능 예측, 전문가 임상 평가, 대규모 독립 구조 벤치마크는 이번 최소 세트에 넣지 않는다. NAT 평가 연동·DockQ와 추가 구조 10건의 검수는 필요할 때 확장한다. 기존 goldset의 “전부 예측” 라벨은 이번 점수에 쓰지 않는다.

이번 입력은 **출처가 고정된 공개 재현 데이터와 명시적인 합성 오류 데이터**다. 신규 항체에서의 정확도나 연구자의 실험 선택 효과를 증명하는 독립 시험셋은 아직 아니다.

## 7. 이번에 실제 확인한 것

- 원본 2건의 기존 해시 및 기준 FASTA 대조, 별도 계산으로 접촉 잔기 39/56 집합 검산 완료.
- 입력 4개와 10개 사례의 파일 참조·JSON Schema 검사 완료. 이상한 서열도 의도한 로직 검사를 위해 스키마 수준에서는 읽을 수 있게 구성했다.
- 채점기 검증 9개 통과: 20점 집계, 19점이어도 치명 실패 차단, 미실행의 총점 제외, 중복·증거 누락·잘못된 상태·버전·검토자 차단, 입력 파일 변조 탐지.
- 10개 오프라인 사례와 격리된 영속 화면을 평가하여 **13/20, 치명 실패 항목 5개**를 기록했다. 별도 실제 Nemotron 정상 입력 1회는 20.117초에 완료했고 Boltz-2 호출은 없었다. 상세 범위와 실패 근거는 [평가 기록](hackathon-evaluation-results.md)에 있다. 전체 실제 모델 20점 평가는 수행하지 않았다.

파일 재생성이 필요하면 `prepare.py`를 실행한다. 이는 입력·기대 접촉·잠금 파일을 갱신하므로 평가 후 무심코 실행하지 않는다. 원본이 바뀌면 먼저 변경 이유와 기대값을 검토하고 데이터 버전을 올린다. 기존 결과를 통과시키기 위해 기대값만 수정하지 않는다.
