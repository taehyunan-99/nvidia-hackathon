# HER2 데모의 구현 범위와 검증 기준

최종 구현 범위는 [프로젝트 개요](overview.md)의 **입력부터 3D 비교·결과 보고까지 전체 흐름**이다.
공개 구조 분석과 Boltz-2 한 건은 위험을 먼저 확인하는 첫 기술 검증 단계이며, 이것만으로 전체 데모가 완성된 것은 아니다.

## 처음 확인할 기술 경로

1. 공개 구조를 읽고 HER2·항체 사슬과 잔기 번호를 올바르게 대응한다.
2. 알려진 구조의 접촉 부위를 재확인하고, 잘못된 입력·누락 정보에서 보류 분기를 확인한다.
3. 실제 계정으로 필요한 Boltz-2 호출 한 건을 수행해 입력 조건·반환 형식·시간·실패 동작을 확인한다.

| 기준 구조 | 확인 목적 | 이것만으로 확인하지 못하는 것 |
|---|---|---|
| [1N8Z: HER2–Herceptin Fab](https://www.rcsb.org/structure/1N8Z) | 공개 구조의 사슬·번호·접촉 부위를 올바르게 읽는지 | 새로운 후보의 결합력·예측 정확도 |
| [1S78: ErbB2–pertuzumab 복합체](https://www.rcsb.org/structure/1S78) | 다른 결합 부위의 구조를 같은 기준으로 비교하는지 | 후보 순위의 실험적 타당성 |

구조 ID만으로 항체 서열·chain·분석 구간을 추측하지 않는다. 실제 파일과 주석을 읽고 대응한다.

## 전체 데모에서 확인할 동작

| 검증할 상황 | 기대하는 동작·확인 근거 |
|---|---|
| 정상 입력 | 후보가 자료 확인·분석을 거쳐 3D 비교와 후보별 결과 보고에 연결된다. |
| 실험 구조로 충분한 경우 | 예측을 생략한 이유와 사용한 구조가 실행 기록에 남는다. |
| 새 복합체 예측이 필요한 경우 | 실제 호출·반환 구조·설정을 기록하고 해당 결과를 비교에 사용한다. |
| 서열·사슬·번호 불일치 | 오류 위치와 이유를 표시하고 그 입력으로 계산을 계속하지 않는다. |
| 당쇄·주변 구조 정보 부족 | ‘없음’과 ‘미확인’을 구분하고 영향받는 접근성 판단을 보류한다. |
| 예측 간 불일치·지표 충돌 | 서로 다른 근거를 보여주고 추가 확인 또는 보류 이유를 남긴다. |
| API 오류·timeout | 실패 상태와 미완료 결과를 표시하며 성공 결과를 꾸며내지 않는다. |
| 화면과 보고서 대조 | 같은 후보·입력·구조 조건을 가리키며 출처와 결과 파일을 확인할 수 있다. |

검증 입력, 기대 결과의 근거, 실제 결과와 실행 설정을 함께 확인한다.
합성 오류 입력은 합성이라고 표시한다. 실행 결과가 생기기 전에는 통과·성능·실험 절감 효과를 기록하지 않는다.

## 데모 동작과 연구 유용성의 구분

공개 구조 재현은 자료 처리와 비교 기능의 검증이다.
새로운 항체에 대한 정확도·보류 판단의 타당성은 검토에 쓰지 않은 구조·실측 자료와 대조해야 한다.
실험 대상 선택에 실제로 도움이 되는지, 기존 방식보다 시간을 줄이는지는 별도의 평가 대상이며 데모 완성만으로 입증되지 않는다.

후속 확인 목록은 결합 자체, 결합 부위, 세포 환경에서의 결합 등 남은 질문을 제시한다. 구체적인 실험 프로토콜·판정값은 정하지 않았다.

## 구현 전에 정할 항목

- 실제 데모 후보 2–3개, 항체 형식, HER2·항체의 분석 구간, 입력 파일과 허용 형식.

- 사용할 모델·엔드포인트·계정 접근, 호출 한도, 실행 시간·비용, timeout과 재시도 한도.
- [ARCHITECTURE](../../ARCHITECTURE.md)의 기술 선택에 대한 실제 호환성, 잠정 AWS 구성의 예산·규격·리전, 접근·데이터 정책, 데모 실행 환경과 제출 방식.

이 항목들은 주제 미선정을 의미하지 않는다. 프로젝트 주제와 전체 구현 흐름은 위와 같으며, 세부 구현 계약은 확인 후 채운다.

웹 서비스의 기능별 완료 조건과 미결정 항목은 [PRD](../../PRD.md)에서 구체화한다. 이 문서는 분석 경로와 과학적 검증의 기준을 유지한다.
