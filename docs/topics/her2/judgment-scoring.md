# 에이전트 판단 채점 — 실제 자료 평가셋 구축과 시험 결과

작성 2026-09-26 22시대. 담당 로직 B.
자료와 도구는 [assets/goldset/](assets/goldset/)에 있다(돌리는 법은 그 폴더의 README).
구조 파일 `assets/goldset/cif/`만 용량 때문에 git 제외이며 `fetch_cif.sh`로 다시 받는다.
모든 수치는 이 세션에서 직접 실행해 얻었다. 확인하지 못한 것은 `[확인 필요]`로 남겼다.

## 1. 한 줄 요약

에이전트 판단을 채점할 **정답 기준을 실제 결정 구조로 만들었고, 채점기가 제대로 동작하는 것까지 확인했다**.
다만 **실모델 측정은 NVIDIA API 429로 막혀 못 했다**. 모델을 부르지 않는 시험은 전부 통과했다.

## 2. 왜 필요했나 — 기존 비교는 채점이 아니었다

`nat-agent-loop.md` §7의 "규칙 모드 대 에이전트" 표는 판단 정확도의 근거가 되지 못한다. 근거 두 가지다.

1. `logic/agent.py:182` `Decider.choose`는 규칙 모드에서도 Nemotron에게 물어본다. 코드에 박힌 `default`는
   모델을 **못 부를 때만** 쓰는 값이다(`agent.py:202`). 즉 두 열은 같은 모델을 한 번에 묻느냐 도구 루프로
   묻느냐의 차이이고, 어느 쪽도 정답이 아니다.
2. `logic/analysis.py:181-192` `pending_measurements`는 `atom_clash`·`surface_exposure`를 **항상** `not_run`으로
   돌려준다. 그래서 `flow.py:769`의 기본값 `"reviewable" if measured and not unmeasured else "needs_confirmation"`은
   현재 구현에서 **언제나 needs_confirmation**이다. 판별력이 0이다.

결론: `reviewable`/`needs_confirmation`은 지금 채점할 수 없다. 기준 자체가 미정이며,
`docs/topics/her2/validation.md:48`이 "독립적인 정답 기준"을 미결정 항목으로 적어 두었다.
**그래서 채점 가능한 다른 지점을 찾아 정답 기준을 만들었다.**

## 3. 평가셋 — 실제 PDB 10건

RCSB 검색 API로 HER2 항체 복합체를 찾아 12건을 얻었고, 이미 쓰는 1N8Z·1S78을 뺀 10건을 평가셋으로 삼았다.
서열·구조 파일 모두 RCSB에서 직접 받았다.

| PDB | 표적 | 항체 | 쓰임 |
|---|---|---|---|
| 3BE1 | HER2 | bH1 (트라스투주맙 골격 이중특이) | 같은 에피토프 양성 |
| 3WSQ | HER2 | 미상 Fab | 다른 에피토프 |
| 5O4G | HER2 | MF3958 | 다른 에피토프 |
| 6ATT | HER2 | 39S | 다른 에피토프 |
| 6BGT | HER2 | **트라스투주맙 변이체** | 변이체 양성 |
| 9L1S | HER2 | **퍼투주맙 T30S/D31A 변이체** | 변이체 양성 |
| 9T3R | HER2 | EPS232 | 부분 겹침 |
| 9T3S | HER2 | EPS226 | 부분 겹침 |
| 4P59 | **HER3** | MOR09825 | 틀린 표적 음성 대조 |
| 8YRY | **HER3** | Hu3f8 | 틀린 표적 음성 대조 |

6BGT·9L1S는 기존 가상 변이체 시나리오를 **실제 변이체**로 바꿀 수 있다는 점에서 특히 값이 있다.

파일: `pdb-sequences.json`, `cif/*.cif`(10건), 수집 스크립트 `fetch_seqs.py`.

## 4. 통과한 시험 (모델·유료 호출 없음)

### 4-1. 구조 조회 판정 10/10

`logic.structures.find_structure`에 실제 10건을 넣었다. 카탈로그에 1N8Z·1S78만 있으므로
정답은 전부 예측 경로다. **10건 모두 맞았다.** 9L1S는 경쇄만 1S78과 같아 부분 일치로 잡혔고,
"부분 일치는 같은 후보로 보지 않는다"는 규칙대로 예측으로 갔다.

다만 이것은 결정론적 함수라 **모델 성능이 아니다**. 스크립트 `probe_match.py`, 결과 `lookup-result.json`.

### 4-2. 접촉 잔기 기준 계산 — 1N8Z로 검산 통과

저장소의 `logic/contacts.py`(4.5Å, 중원자)를 그대로 써서 12건 전부 계산했다.
**1N8Z가 39잔기로 나왔고 저장소가 적어 둔 값과 같다** — 계산 방법이 검증됐다.

계산 중 저장소 값과 어긋나는 것을 하나 찾았다. 1S78이 처음에 114로 나왔는데,
**비대칭 단위에 복합체가 2벌** 들어 있었다(표적 A·B, 항체 C·D·E·F). 벌로 쪼개니 56·58이 되고
앞의 56이 a02가 적어 둔 값과 같다. 예측 구조는 항상 1벌이므로 **2벌 기준과 그대로 비교하면 F1이 틀린다.**
저장 파일은 벌 단위로 나눠 두었다. 나머지 11건은 모두 1벌이다.

스크립트 `calc_contacts.py`, 결과 `reference-contacts.json`.

### 4-3. 에피토프 공통 좌표 변환 — 생물학적으로 타당

엔트리마다 표적 construct 시작 위치가 달라 잔기 번호를 그대로 못 비교한다.
1N8Z 표적 서열을 기준으로 difflib로 옮겼다(대응 실패는 9L1S 1건뿐).

1N8Z 좌표에서 에피토프가 위치별로 뚜렷이 갈렸다.

- 557~600: 1N8Z, 3BE1, 6BGT — 트라스투주맙 계열
- 235~268: 1S78, 9L1S, 9T3R, 9T3S — 퍼투주맙 계열
- 332~395: 3WSQ / 140~168: 5O4G / 178~211: 6ATT — 각기 다른 자리

트라스투주맙과 퍼투주맙이 HER2의 서로 다른 자리를 무는 것은 알려진 사실이고, 계산 결과가 그것과 맞는다.
**이것이 이 채점 기준을 믿을 수 있는 근거다.**

스크립트 `epitope_overlap.py`, 결과 `epitopes-1n8z-coords.json`.

### 4-4. 채점기 검증 7/7

`score_epitope.py`가 예측 에피토프와 기준 에피토프를 집합으로 비교해 P/R/F1을 낸다.
결정 구조를 예측 자리에 넣어 시험했다.

| 사례 | P | R | F1 | 기대 | 결과 |
|---|---|---|---|---|---|
| 1N8Z → 1N8Z (자기 자신) | 1.0 | 1.0 | **1.0** | 1.0 | 통과 |
| 6BGT(트라스투주맙 변이체) → 1N8Z | 0.900 | 0.947 | **0.923** | 높음 | 통과 |
| 3BE1(트라스투주맙 골격) → 1N8Z | 0.941 | 0.842 | **0.889** | 높음 | 통과 |
| 9L1S(퍼투주맙 변이체) → 1S78 | 0.875 | 0.808 | **0.840** | 높음 | 통과 |
| 1S78(퍼투주맙) → 1N8Z | 0.0 | 0.0 | **0.0** | 0 | 통과 |
| 5O4G(다른 자리) → 1N8Z | 0.0 | 0.0 | **0.0** | 0 | 통과 |
| 9T3R → 1S78 | 0.667 | 0.385 | **0.488** | 부분 | 통과 |

**예측 구조만 나오면 바로 채점할 수 있다.**

### 4-5. 관문 구동 10/10

실제 10건을 후보로 넣고 도구를 끝까지 구동했다(모델 없음, 예측 응답은 스텁).
**10건 모두 도구 5개를 밟고 completed로 끝났고 거부는 0건이다.**
`check_input → lookup_public_structure → predict_structure → compare_structure → submit_opinion`.

구동 중 **모델이 실제로 시험받는 갈림길**을 찾았다. 공개 구조와 완전히 일치하지 않으면
`allowed_tools`가 `predict_structure`와 `hold_candidate`를 **동시에** 연다(`agent_session.py`).
`hold_candidate`의 도구 설명은 "예측 입력으로 쓸 서열 자체가 없거나 너무 짧을 때만"이라고 못 박는다.
그러므로 **서열이 멀쩡한데 보류를 고르면 명백한 오답**이고, 이 10건의 정답은 전부 예측이다.
정답이 코드가 아니라 도구 설명에 적혀 있어 채점이 가능하다.

(이 갈림길은 내 구동 스크립트가 도구를 알파벳순으로 골라 10건 모두 보류로 간 덕에 드러났다.
스크립트 버그였고 예측 우선으로 고쳤다.)

스크립트 `gate_run.py`, 결과 `gate-run.json`.

## 5. 막힌 것 — 실모델 측정

판정 흔들림 측정(같은 후보를 5회씩 돌려 판정이 갈리는지)을 **두 번 시도해 두 번 다 429로 실패했다.**

| 시각 | 조건 | 결과 |
|---|---|---|
| 22:20 | trastuzumab 1회 | 빈 응답 2회 → 429. 도구 4개까지 진행 |
| 22:31 | trastuzumab·pertuzumab 5회, `--sleep 30` | 첫 실행 3번째 도구에서 429 |

무효 기록은 `work/probe-INVALID-429-2220.jsonl`, `work/measure-variance-INVALID-429-2231.jsonl`로 남겼다.

### 알아낸 것

- **한도 헤더가 없다.** `integrate.api.nvidia.com`은 `RateLimit-*`·`Retry-After`를 하나도 주지 않는다
  (22:35 직접 확인, GET `/models`와 POST `/chat/completions` 모두 200이면서 헤더 없음).
  남은 횟수를 알 방법이 없다.
- 공식 수치는 저장소에도 `[확인 필요: 공식 한도 수치]`로 남아 있다(`nvidia_client.py:35`).
  무료 티어 40 RPM이라는 커뮤니티 수치가 있으나 NVIDIA 공식 보장치는 아니다
  (출처: NVIDIA 개발자 포럼 rate-limit 증설 요청 글들).
- **빈 응답이 한도의 앞 단계일 가능성이 있다.** 22:20 실행에서 빈 응답 2회 직후 429가 왔다.
  맞다면 재시도 2회는 빈 응답을 구제하지 못한다 — 원인이 모델의 일시적 실수가 아니라 한도이기 때문이다.
  인계 문서 §6-3이 "429와 빈 응답은 기록에서 구분되지 않는다"고 적은 것과 같은 뿌리로 보인다.
  **[확인 필요: 관측 2건뿐이라 단정할 수 없다]**
- 22:31 실행은 22:30의 헤더 확인 직후여서 간격이 거의 없었다. `--sleep 30`은 실행 **사이** 간격이라
  첫 실행에는 적용되지 않는다.

## 6. 다음에 할 일

1. **한도가 풀린 뒤 판정 흔들림 측정.** 명령은 아래. 로그를 반드시 함께 남긴다(429와 빈 응답 구분용).
   ```
   .venv/bin/python -u -m logic.measure_agent --scenario trastuzumab,pertuzumab \
     --repeat 5 --no-rule --sleep 30 --out measure-variance.jsonl > work/measure-variance.log 2>&1
   ```
2. **보류 대 예측 갈림길 채점**(§4-5). 실제 10건을 모델에게 물어 보류를 고르는 비율을 센다.
   Boltz-2를 부르지 않게 예측 직전에 끊으면 유료 예측 호출은 0회다.
3. **예측 에피토프 F1**(§4-4). Boltz-2로 10건을 예측해 채점기에 넣는다. 유료 예측 10회.
4. **평가셋을 `logic/measure_agent.py` 시나리오로 승격.** 지금 시나리오 5개는 전부 인공이거나
   1N8Z·1S78 기반이다. 실제 10건을 넣으면 시험 범위가 넓어진다.
5. **`work/goldset/`은 git 제외다.** 남길 가치가 있다고 판단되면 저장소로 옮겨야 한다
   (스크립트는 `logic/`, 구조 파일은 용량 때문에 재다운로드 스크립트만).
