## 새 항체의 구조 결과는 맞았는가

두 신규 사례의 실험 구조는 에이전트에 주지 않고 평가자만 보유했다.
에이전트에는 해당 실험 구조에서 확인한 실제 표적·중쇄·경쇄 서열을 입력했다.
표적 construct 서열이 실험·예측에서 정확히 같은지 확인한 뒤 label 잔기 번호로 비교했다.
실험 구조는 비대칭 단위의 표적 A와 항체 B/C를 사용했으며 대칭 확장은 하지 않았다.

| 8JYR H2Mab-119 | 19 | 14 | 0 | 0 / 0 / **0.000** | 0.8821 |

**두 신규 항체 모두 이번 예측은 실험 접촉 위치를 맞히지 못했다.** 신뢰도 0.88·0.85를 실제 정확도로
해석할 수 없다는 반례다. 3N85의 예측은 에이전트가 아니라 규칙 대체 경로가 실행한 실제 Boltz-2 결과다.

### 이 점수의 검산

- 제품의 원자 파싱·공간 격자 접촉 알고리즘과 별도로, mmCIF 열을 직접 읽어 모든 표적–항체
  중원자 쌍을 거리 제곱 ≤ 4.5² Å²로 대조하는 계산을 작성했다.
- 두 실험 구조와 두 예측 구조 모두에서 **독립 계산과 제품 계산의 잔기 집합 전체가 일치**했다.
  CIF 구문 해석 라이브러리 gemmi는 공통으로 사용한다.
- 원자를 못 읽거나 사슬·표적 서열이 맞지 않으면 0점으로 처리하지 않고 평가를 실패시킨다.
- 원본 구조와 예측 파일의 SHA256을 검증했다. 따라서 이번 0점은 앞서 발견한 “원자 0개” 파싱 오류가 아니다.
- 이 지표는 정해진 접촉 기준의 위치 일치도다. 결합 강도·치료 효능·변이 효과를 측정하지 않는다.

## 데이터 신뢰성과 한계

새 평가 자료는 RCSB의 [8JYR](https://www.rcsb.org/structure/8JYR)와
[3N85](https://www.rcsb.org/structure/3N85)에서 받았다.
구조 원본 다운로드 URL·UTC 시각·SHA256·입력 서열·사례별 기대값과 코드 해시를
[실행 전 고정한 manifest](assets/goldset/generated/agent-benchmark-manifest.json)에 보존했다.
이 두 사례를 보고 프롬프트·제품 코드를 조정하지 않았다.

단, 두 사례는 개발용으로 쓰지 않았다는 뜻이지 모델 사전학습에서 제외됐다는 뜻은 아니다.
작은 목적 표본으로 전체 항체의 정확도를 추정할 수 없다. 알려진 항체 두 건은 개발 회귀 대조이며
hold-out 성능에 섞지 않는다. 합성 대조군 네 건을 실제 실험 데이터로 표현하지 않는다.

현재 `lookup_public_structure`의 실제 카탈로그는 **1N8Z·1S78 두 건뿐**이다.
8JYR·3N85가 공개돼 있어도 찾아 재사용하지 못한다. 이번 신규 사례의 “예측 경로 정답”은
이 제한된 구현의 정책 기준이며 **공개 구조 검색 능력이 좋다는 의미가 아니다**.

## 개선 우선순위

1. **호출 안정성:** 90초 간격으로도 모델 실행 5/6에서 429가 났다. 호출 한도·마지막 불필요한
   자연어 응답 호출·실패 시 대체 동작을 먼저 다뤄야 한다. 재시도 성공만 골라 보고하지 않는다.
2. **공개 구조 검색 범위:** 실제로 공개된 복합체를 찾아 재사용할 수 있도록 조회 범위를 넓혀야 한다.
3. **예측 품질:** 이번 신규 두 항체의 접촉 F1은 모두 0이다. 신뢰도나 샘플 수만으로 품질을 보장할 수 없다.
   개선 설정은 별도 개발 데이터에서 고르고 새로운 hold-out에서 다시 검증해야 한다.
4. **근거 계산:** 충돌·표면 노출은 여전히 미계산이다. `needs_confirmation`을 강제하는 것은 과신 방지이며
   해당 분석이 구현됐거나 판단 성능이 올라갔다는 증거가 아니다.

## 429 완화 후속 수정 — 실제 API 재검증 완료

후보 간 대기만으로 내부 LLM 연속 호출을 제어하지 못했던 부분을 수정했다.
`logic/nat_model.py`의 NAT NIM 어댑터는 같은 프로세스의 요청 시작 간격을 15초로 제한한다.
429는 최대 3번 시도하며 30초·60초와 서버 `Retry-After` 중 긴 시간을 따른다.
서버가 120초 넘는 대기를 요구하면 재시도하지 않는다. 부분 스트림을 받은 요청도 재생하지 않는다.
승인된 terminal 상태에서는 고정 종료 문장을 반환하여 마지막 LLM 호출을 생략한다.
거부된 제출은 terminal이 아니므로 모델이 계속 수정할 수 있다.
응답 상태·요청 시각·허용 목록의 제한/요청 ID 헤더를 `nim_http` 로그에 남긴다.
키·프롬프트·서열은 이 진단 로그에 기록하지 않는다. 다른 프로세스나 같은 키의 외부 사용은
이 제한기가 제어하지 못한다. 15초는 확인된 계정 한도가 아니라 보수적인 시작값이다.

관련 오프라인 검사 17개 통과, 1개 live 검사 생략. 로직 전체 138개 통과, 1개 live 검사 생략.
전체 저장소 검사는 156개 통과, 18개 생략했다. 실제 워크플로 생성도 추론 호출 없이 통과했다.
최초 실행은 자동 승인 검토가 차단했으나, 사용자의 계속 진행 지시 후 승인되어 아래 시험을 완료했다.
[재검증 실행 파일](assets/goldset/check_paced_agent.py)은 원래 8사례와 구조 예측 캐시를 사용하고,
원본 평가 기록을 보존한다. 새 Boltz 호출은 차단한다. 새 결과는 별도 `paced-agent-*` 파일에 쓴다.


2026-09-27 KST 01:57–02:07, 같은 8개 입력·정답 기준으로 한 회씩 실행했다.
회차 안에서는 제품 코드 해시를 고정했고, 원래 평가 실패 기록을 보존했다.

따라서 **모델 판단·호출 복구 회귀 시험**이며 새 구조 예측 품질 시험이 아니다.

| 짧은 중쇄 | 예, 보류 | 1 / 4 | 73.64초 |
| 8JYR | 예, 캐시 예측 근거로 의견 제출 | 2 / 7 | 147.74초 |
| 3N85 | 예, 캐시 예측 근거로 의견 제출 | 1 / 7 | 107.90초 |

- **권장 경로 + 규칙 대체 없이 완료: 2/6 → 6/6.** 수정 후 규칙 대체 0건.
- HTTP 응답은 200 **25회**, 429 **7회**. 429 모두 다음 시도에서 복구했으며 최종 미처리 오류는 0건.
  `clean_success`는 미처리 오류가 없다는 뜻이다. HTTP 오류조차 없었던 사례는 **1/6**뿐이다.
- 요청 시작 간 최소 간격 **15.000589초**, 승인된 종료 뒤 생략한 모델 요청 **6회**.
- 입력 오류 2건은 각각 HTTP 요청 0회로 거부. 전체 최종 상태·판정은 8/8 기대값과 일치.
- 새 Boltz 호출 **0회**, 기존 응답 캐시 사용 **2회**. 기존 두 예측의 접촉 F1=0은 그대로다.
- 서버는 수집 대상 `Retry-After`·rate-limit·request-ID 헤더를 반환하지 않았다.
  어느 계정 한도가 적용됐는지는 여전히 확인할 수 없다. 15초 간격만으로 429를 제거하지 못했다.

완주 개선을 관측했고 7번의 복구 경로를 직접 확인했지만, 전후 실행 시각이 다르고
표본도 작아 간격 조정만의 인과 효과나 일반 성공률 100%를 주장하지 않는다.
현재 성과는 **API 제한 때문에 중단되던 작업을 복구하여 끝내는 것**이다.
지연 및 실제 새 항체 구조 예측 정확도 개선은 별도 남은 작업이다.

## 회차 뒤 코드 수정과 지표 해석 정정 — 2026-09-27 Claude 이어받음

### `최종 판정 8/8 일치`는 판단 품질의 증거가 아니다

`reviewable` 판정은 현재 어느 경로에서도 도달할 수 없다.
`analysis.pending_measurements`가 `atom_clash`·`surface_exposure`를 항상 미계산으로 넣고
(`logic/analysis.py`), `flow._compare`가 실험 구조·예측 구조 양쪽에서 그것을 더한다(`logic/flow.py`).
그래서 `submit_opinion`의 reviewable 거부 조건(`not measured or unmeasured`)이 늘 참이고,
규칙 경로의 reviewable 선택지도 비어 있다. 모델 필요 4사례의 기대 판정이 모두
`needs_confirmation`이므로, 이 지표는 **가드가 작동했는지**를 재는 것이지
에이전트가 옳게 판단했는지를 재지 못한다. 근거가 모자란데 과신하는 모델이 있어도 잡히지 않는다.

실측 확인: 8사례 모두 도구 거부 0건이었다(`generated/paced-agent-results.jsonl`).
모델이 reviewable을 시도해 왕복을 낭비한 일은 이 회차에 없었다.
`atom_clash`·`surface_exposure`를 구현해 reviewable을 도달 가능하게 만들기 전에는
판단 정확도를 이 8사례로 주장하지 않는다. 두 계산은 A-02·A-03 합의 뒤의 별도 과제다.

각각 실패하는 테스트를 먼저 쓰고 고쳤다. 전체 검사 **168 passed, 18 skipped**
(추가 12건은 새 테스트다). 측정 산출물은 하나도 덮어쓰지 않았다.

### 관측 추가 — 인계서 우선순위 2

복구된 429는 `agent_errors`까지 올라오지 않아 이전에는 과소계수됐다.
이제 `nat_model`이 요청마다 시도를 남기고(`record_attempt`/`take_attempts`, 로그 `nim_http`와 같은 내용에
