# 팀원 변경 통합 리뷰와 성능 개선 우선순위

> 현재 적용 상태: 공개 전용 연결은 채택하지 않고 실험·예측 모두의 좌표를 처리하는 공통 계산기로 구현했다. 아래 18/20과 '공개 두 후보에 한정' 제안은 적용 전 리뷰 기록이다. 현재 변경·검증은 다음 절을 기준으로 읽는다.

## 현재 적용 결과 — 공통 좌표 계산

### 다운로드된 팀원 검증 입력 확인

사용자가 지정한 로컬 다운로드의 `01-trastuzumab-pertuzumab.zip`, `02-39s-fab37.zip` 안 `review-input.json`을 읽고 현재 Flow에서 재실행했다. 원본 ZIP·FASTA·JSON은 수정하지 않았다. 모델은 규칙 기준선, 예측은 호출을 기록한 뒤 차단하는 대역을 사용했으며 실제 Nemotron/Boltz-2 호출은 0회다.

| 입력 | 현재 실행 결과 | 의미 |
|---|---|---|
| 01 원본: 607잔기, trastuzumab/pertuzumab | 두 후보 completed, 1N8Z/1S78 재사용, 예측 시도 0 | 정상 흐름의 기준선으로 지금 사용 가능 |
| 02 원본: 624잔기, 39S/Fab37 | 두 후보 입력 검사에서 failed, 예측 시도 0 | 데이터 오류로 단정할 수 없으며 현재 제품의 607잔기 고정 범위와 불일치 |
| 02 진단용 파생 입력: 표적만 기존 607잔기로 변경 | 로컬 조회는 두 후보 모두 불일치, 예측 선택 2회 후 대역에서 차단 | 입력 `sources`의 6ATT/3N85를 실제 조회에 활용하지 않는 별도 한계를 재현 |

02의 추출 폴더 JSON과 ZIP 안 JSON의 해시도 일치한다. `find_structure`는 현재 로컬 1N8Z/1S78만 확인하며 입력의 출처를 인자로 받지 않는다. 직접 입력 화면은 FASTA를 받고 `sources=[]`를 전송하므로 출처 기반 검증에는 JSON 메타데이터 경로 또는 별도 출처 입력 연결이 필요하다. 첨부 안내의 '현재 화면은 모의 실행·service.app만 실제 경로' 설명은 현재 저장형 live worker와 다르므로 최신 실행 안내로 사용하지 않는다.

이 두 파일은 지금 사용할 회귀·확장 검증 입력이 맞다. 다만 공통 좌표 계산이 구현됐다는 사실과 '입력 출처에서 적합한 구조를 확보해 재사용하는 전체 에이전트'가 검증됐다는 사실을 구분한다. 다음 검증에는 02의 표적 범위 정합, 출처의 PDB ID·표적·중쇄·경쇄·실제 label 사슬 대응, 출처 충돌, 이름/순서 불변성, 불필요한 예측 방지와 계산 보류 사유가 포함돼야 한다. 구조 이름 두 개를 로컬 목록에 추가하는 것으로 일반 출처 조회를 대신하지 않는다.

개인 실행 근거는 `tmp/integration-review/download-inputs/summary.json` 및 각 원본/진단 실행의 `result.json`·`observation.json`에 보존했다. 이번 확인은 새 출처 조회 기능을 구현한 작업이나 실제 모델의 판단 품질 측정이 아니다.

2026-09-27 사용자 수정 방향을 반영했다. 공개 테스트 입력과 직접 입력에 따라 계산 기능을 나누지 않는다. 구조를 확보한 뒤 같은 사슬·서열·좌표 검증과 같은 계산을 실행한다. 사전 계산 결과 파일을 제품 응답에 끼워 넣던 초기 adapter는 제거했다.

- `logic/surface_analysis.py`: A-02의 순수 기하 계산 코드를 재사용해 모든 유효 좌표의 단백질 SASA·양쪽 매몰 면적을 계산한다. 원본 서열 안의 입력 구간을 유일한 연속 일치로 대응시키고 원본 label 번호와 입력 위치를 구분한다. 누락 잔기는 보존하며 일부 좌표를 전체 구조로 해석하지 않는다.
- 관측 NAG와 공유결합 주석·좌표 대응이 검증되면 같은 단백질 원자에서 core/context 차이를 계산한다. 당 없음·다른 당 종류·대체 좌표·부분 점유율은 출처와 무관하게 보류한다. 이 제한은 공개 사례만 허용하는 목록이 아니라 현재 검증한 계산 조건이다.
- `logic/prediction_validation.py`: 좌표·서열·사슬 역할이 맞지 않는 예측은 `ready` 등록 전에 중단한다. 부분 좌표가 명확하게 대응되는 경우에는 관측 범위와 누락을 보존한다. 높은 신뢰도 점수로 손상 구조를 통과시키지 않는다.
- 의견은 같은 후보·조건의 evidence만 연결한다. 모델 자유 설명은 진단 기록으로 남고, 정상 결과 보고의 과학적 문장은 검증된 근거에서 구성한다. 값·단위 바꿔치기나 효능 단정을 결과 문장으로 그대로 저장하지 않는다. 모델 판단 정확도 자체가 향상됐다는 뜻은 아니다.
- 화면은 표면적·매몰 면적·관측 당 감소량을 Å²로 표시하며 조건별 근거·다음 질문·관측 당의 3D 표시를 함께 전환한다. 당 좌표가 제공되지 않은 조건을 '가림 0'으로 표현하지 않는다.

## 결론

팀원 변경은 모두 main에 반영되어 있다. 통합 검사에서 근거 연결 오류 두 건을 재현해 수정했다. 고정 `hackathon-v1` 사례와 저장형 화면의 재점검은 **18/20, 치명 실패 S3 1건**이다. 준비 완료가 아니다. 이 점수는 모델 정확도나 구조 예측 성능이 아니라 오프라인 제품 관문 점검이다.

특히 E3/E4는 고정된 `reviewable` 입력만 거부된다. 같은 과장 문장을 `needs_confirmation`으로 제출하면 저장되는 우회를 추가 재현했다. 따라서 고정 점수 상승을 의견의 사실성 개선으로 해석하면 안 된다. [과거 13/20](hackathon-evaluation-results.md)은 다른 코드의 기록이며 그대로 보존한다.

## 공식 자료 조사와 적용 한계

2026-09-27 공식 문서를 다시 확인했다. 아래는 구현·설치 완료 사실이 아닌 조사 결과와 적용 제안이다.

1. **템플릿 미지원의 일반화는 철회해야 한다.** [Boltz-2 NIM 1.8 추론 문서](https://docs.nvidia.com/nim/bionemo/boltz2/1.8.0/inference.html)는 protein polymer의 `structural_templates`를 명시하고, [릴리스 노트](https://docs.nvidia.com/nim/bionemo/boltz2/latest/release-notes.html)는 CIF/PDB 템플릿 도입을 기록한다. 다만 이는 배포형 NIM 문서이며 현재 `health.api.nvidia.com` 호스팅 endpoint의 버전·지원은 실호출로 확인하지 않았다. 제품 클라이언트는 현재 recycling/sampling/diffusion 설정을 전달한다. 지원 확인 후 정답 계면이 유출되지 않는 템플릿 실험을 제안한다. Pocket의 문서상 binder는 ligand이므로 항체 사슬 제약으로 임의 전용하지 않는다. 친화도 기능도 ligand 대상이며 항체 nM 예측으로 바꾸지 않는다.
2. **자세까지 검산한다.** [DockQ 공식 저장소](https://github.com/wallnerlab/DockQ)는 DockQ·iRMSD·LRMSD·접촉 관련 지표와 명시적 사슬 매핑을 제공한다. 기존 4.5 Å 표적 잔기 집합 F1과 다른 지표이므로 점수를 섞지 않는다. 실험 기준 구조가 필요한 평가 도구여서 정답이 없는 새 후보의 런타임 판정기로 쓸 수 없다.
3. **모델 판정기보다 결정론적 계약 검사를 먼저 연결한다.** [NAT custom evaluator 공식 문서](https://docs.nvidia.com/nemo/agent-toolkit/latest/extend/custom-components/custom-evaluator.html)는 사용자 평가기와 trajectory 소비를 설명한다. 저장소의 기존 평가기·파일 해시·도구 호출 제약을 재사용하고 모델 설명 평가는 보조로 둔다. 문서 버전과 로컬 NAT 의존성의 실제 API 호환성은 구현 시 확인한다.

샘플 수나 신뢰도만 높이는 방식은 팀원 관측으로 이미 반례가 있다. 이를 전체 모델의 불가능성으로 일반화하지 않고, 지원되는 입력·선택 정책을 검증 가능한 가설로 나누는 것이 다음 조사·실험 방향이다.

### 판단: 제한된 근거 추가는 추천, 현재 산출물의 단순 연결은 보류

### 직접 확인한 연결 장애

1. **입력의 생물학적 범위는 일치하지만 번호는 다르다.** A-01의 전체 HER2 1,255잔기 중 23–629가 현재 서비스의 607잔기와 정확히 같고, 정규화한 두 항체 중쇄·경쇄도 각각 정확히 같다. 그러나 A-02 `sequence_position`은 원래 전체 서열 기준이다. 1S78 대응표에는 현재 입력 범위 밖 630–646의 17잔기도 남아 있다. 현재 입력 위치와 원본 위치를 구분하고, 범위 밖 좌표를 접촉 계산 범위나 입력 대응으로 오인하지 않게 처리해야 한다.
2. **구조 파일을 함께 전달해야 한다.** A-02 assembly 파일과 현재 서비스 ASU 파일은 두 후보 모두 SHA256이 다르다. A-02 Evidence만 기존 구조 ID에 붙일 수 없다. 해당 assembly 파일·대응표·artifact 등록을 함께 검증해야 한다.
3. **현재 보고 함수는 조건을 섞는다.** A-03 근거를 후보 ID만 바꿔 임시로 추가했을 때 `_opinion_facts`는 현재 core, A-03 core, A-03 context 세 조건의 측정값을 한 목록에 모았다. `_report`는 이를 현재 core 의견에 연결한다. 따라서 조건별 수집·의견 연결과 중복 core 측정값 정리가 필요하다. 스키마의 필드 타입 검증만으로 이 참조 오류를 잡을 수 없다.
4. **화면의 성분 선택도 계산 조건과 맞춰야 한다.** 현재 3D의 '당·기타 성분'은 표적/항체 사슬과 물을 제외한 다른 성분을 넓게 표시한다. A-03은 특정 assembly의 관측 NAG만 포함한다. 조건 선택과 실제 당 identity를 동기화하지 않으면 계산에는 제외한 성분을 같은 조건으로 보여줄 수 있다. 정렬 행렬도 현재 뷰어가 소비하지 않으므로 이번 최소 적용에서 자동 중첩 비교를 약속하지 않는다.
5. **평가 점수가 자동으로 오르지는 않는다.** `atom_clash=not_run`, `whole_range_accessibility=unknown`은 유지된다. 현재 전체 보류 규칙에 값을 추가해도 E1의 주제별 판정은 해결되지 않으며, 이미 재현한 과장·단위 오류도 별도로 차단해야 한다.

- A-03 원본/구현 해시 검사: 불일치 파일은 현재 `service.schema.json` 한 개였다. 에이전트 이벤트 계약 변경 이후의 해시이므로, 계산 입력 손상과 구분하되 현재 계약 검증 후 기록을 갱신해야 한다.
- A-03 전체 재생성 byte 비교: 첫 차이는 summary의 Python 실행 버전 `3.12.10` 대 `3.13.9`였다.

원인을 확정하기 위해 두 계산을 별도 폴더에 다시 생성하고 JSON의 모든 필드와 CSV bytes를 비교했다. A-02의 표면/접촉 CSV는 모두 같았고, summary의 RMSD 차이는 약 2.22×10⁻¹⁶ Å, 계약 조각의 정렬 관련 숫자 11곳은 최대 약 5.68×10⁻¹⁴ 차이였다. 그 외 summary 차이는 Python 버전뿐이었다. A-03은 당 목록·계약 조각·CSV가 모두 byte 일치했고 summary는 Python 버전만 달랐다. 따라서 이 재실행에서 표면 계산값 변경은 발견하지 않았지만, 기존 byte/해시 테스트 3개의 실패 상태는 그대로 남긴다. 원본 해시 검증은 유지하고 플랫폼별 수치 검증과 실행 메타데이터 비교를 구분하는 정리가 필요하다. 근거는 개인 `rebuild-comparison.json`에 있다.

두 산출물의 개별 구조·조건·근거 스키마 및 A-03→A-02 의존 해시 검사는 현재 계약으로 통과했다. 기존 `.venv`에는 Biopython이 없어 최초 수집이 실패했으며, 저장소의 고정 requirements를 `uv run --locked --with-requirements ...` 임시 환경에 적용했다. 제품 의존성·lock 파일은 변경하지 않았다. Dockerfile은 이미 이 계산 의존성을 설치하지만 로컬 기본 `uv run --locked`만으로는 계산 검사가 재현되지 않는 차이가 있다.

기존 계산 파일을 읽고 검증하는 단일 관측은 약 **0.233초**였다. 이는 전체 worker·화면 응답 시간이 아니다. 공개 두 구조에는 원본·입력 범위·계산 설정·구현 해시가 일치하는 사전 계산값을 사용하는 방식이 합리적이며, 매 요청 전체 재계산이나 임의 신규 후보 재사용은 추천하지 않는다.

이번 별도 재생성의 소요는 A-02 **44.826초**, A-03 **44.969초**였다. 두 프로세스를 함께 실행한 로컬 단일 관측이며 독립 운영 지연이나 처리량 보장이 아니다. 알려진 공개 두 입력에 매번 재계산을 추가하는 것보다 검증된 고정 결과를 연결할 이유가 된다.

### 적용한다면 최소 범위

첫 적용은 **공개 두 후보에 한정해 접촉·매몰 면적·관측 당의 표면 감소·자료 누락을 조건별 근거로 전달**하는 것이다. 전체 SASA·최소 거리·반지름 겹침·전역 정렬 RMSD는 상세 자료로 남기고 후보 점수로 사용하지 않는다. 확인할 결과는 다음 네 가지다.

- 후보·조건·구조 파일·근거·다운로드가 동일한 출처를 가리키며 후보 이름/순서를 바꿔도 대응이 유지됨.
- 같은 후보의 core/context를 분리하고 숫자·단위·적용 범위를 그대로 보고함.
- 범위 밖 잔기·누락 원자·미관측 당·충돌 미판정 상태를 숨기지 않음.
- 기존 접촉·예측·실패 경로는 보존하며 새 질문에 답할 수 있는지 사람이 보고서 전후를 비교함.

이 조건을 충족하면 적용 가치가 있다. 현재 상태 그대로의 파일 연결이나 에이전트 종합점수 상승을 목표로 한 연결은 추천하지 않는다. 이번 검토용 스크립트·기준 실행·비교 결과는 Git 제외 `tmp/integration-review/a02-a03-review.py`와 `tmp/integration-review/a02-a03-review/`에 보존했다.
