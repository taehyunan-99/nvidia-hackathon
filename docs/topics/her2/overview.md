# Bio-3 — HER2 항체 후보 검토 에이전트

현재 진행하는 프로젝트는 **HER2와 항체 후보 2–4개의 결합 부위·접근성·구조상 문제를 비교하고, 다음 실험에서 확인할 질문과 근거를 제시하는 에이전트**다.
해커톤 제출을 위해 **입력 → 자료 확인 → 필요한 구조 예측·분석 → 3D 비교 → 결과 보고**까지 전체 흐름을 구현한다.

## 해결하려는 문제

항체 후보마다 서열·보유 구조·결합 가설과 근거 수준이 다르면 같은 기준으로 비교하기 어렵다.
어느 후보를 먼저 실험할지뿐 아니라, 어떤 정보가 빠졌고 무엇을 확인해야 하는지도 함께 설명해야 한다.
이 프로젝트는 후보별 검토 근거·판단이 어려운 이유·다음 확인 항목을 한 결과로 묶는다.

현재 산출물의 직접 목적은 **해커톤 심사위원에게 위 흐름을 보여주는 데모**다.
데모의 업무 시나리오는 연구자의 항체 후보 비교와 후속 실험 검토이며, 실제 사용 조직·실측 효용까지 확정된 운영 서비스는 아니다.

## 입력과 분석 범위

| 입력 | 용도 |
|---|---|
| 고정 HER2 표적 | P04626 23–629의 607잔기를 자동 제공하며 입력과 출처를 대조 |
| 항체 후보 2–4개의 중쇄·경쇄 FASTA | 후보 구분, 항체 서열과 구조의 대응 확인 |
| 후보별 PDB 출처(선택) | 중쇄·경쇄와 표적 대응을 확인한 실험 복합체만 재사용. 항체 단독 구조는 서열 근거로 구분 |
| 구조에 포함된 관측 당·주변 자료 | 확보된 좌표만 조건 비교에 사용. 구조 업로드 분석은 현재 직접 입력에서 제공하지 않음 |

HER2 세포외 영역과 항체의 항원 결합 부위를 중심으로 분석한다. 항체 형식·실제 분석 구간·사슬·잔기 번호를 확인하며, 구체적인 데모 후보와 입력 구간은 [검증 기준의 미정 항목](validation.md#구현-전에-정할-항목)을 따른다.

## 제공할 결과

| 결과 | 담을 내용 |
|---|---|
| 3D 구조 비교 | 결합 부위·접촉 잔기·당쇄·주변 구조·충돌 또는 누락 위치 |
| 후보별 비교표 | 분석 조건, 근거 종류, 접촉·표면 노출·충돌·구조 신뢰도·자세 일관성 |
| 검토 의견 | 후속 실험 검토 가능 / 추가 확인 / 보류 및 해당 범위·이유 |
| 후속 확인 목록 | 풀어야 할 질문, 필요한 자료·실험 검토 항목, 출처 |
| 실행 근거 | 사용한 입력·구조·모델 설정·도구 실행 상태와 결과 파일(JSON/CSV) |

모든 결과에서 **실험에서 확인한 사실 / 계산으로 얻은 결과 / 미확인 항목**을 구분한다.
자료가 부족하면 해당 판단을 보류하고, 근거가 충돌하면 한 점수로 숨기지 않는다.

## 이 프로젝트의 비교 관점

같은 후보를 HER2–항체 중심 구조에서 검토한 결과와, **확보한 당쇄·주변 구조를 포함한 결과**로 비교한다.
추가된 구조 조건 때문에 판단이 달라졌다면 위치와 이유를 보여준다. 없는 당쇄 자료를 ‘당쇄가 없음’으로 해석하지 않는다.

구조상 우려를 표시하는 일과 실제 결합·치료 효과를 증명하는 일은 다르다.
후보 비교표는 결합력·치료 효과·부작용 확률의 순위가 아니며, 전체 IgG와 실제 세포 환경을 자동으로 대변하지 않는다.
새 항체 생성·추가 학습·임상 판단은 현재 설계에 포함하지 않는다.

## 팀 작업 분담

팀은 사용자 포함 총 3명이다.

| 인원 | 담당 영역 |
|---|---|
| 1명 | 서비스: 프런트엔드·백엔드·호스팅 |
| 2명 | HER2 분석 로직과 에이전트 워크플로우 |

개인별 공개 담당 소개는 [README의 팀](../../../README.md#팀), 현재 서비스·로직 연결 규격은 [서비스 계약](../../frontend-hosting/temporary-contract.md)을 따른다. 추가 세부 작업은 진행하면서 나눈다.
서비스와 분석 작업을 연결할 입력·결과·진행 상태·오류 표현은 구현 과정에서 함께 맞춘다. 한쪽에서 상대 영역의 API나 데이터 형식을 추측해 확정하지 않는다.
