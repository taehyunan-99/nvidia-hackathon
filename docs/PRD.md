# PRD — HER2 항체 후보 검토 웹 서비스

작성일: 2026-09-25. 상태: 구현 기준 초안. 기능 구현·배포·분석 성능은 검증 전이다.

목적과 해석 경계는 [INTENT](intent/INTENT.md), 시스템 구성은 [ARCHITECTURE](ARCHITECTURE.md), 선택 이유는 [ADR](ADR.md)을 따른다. 이 문서는 필요한 기능과 관찰 가능한 완료 조건을 정의한다.

## 1. 목표와 결정 상태

연구자의 HER2 항체 후보 검토를 시나리오로, **입력 → 자료 확인 → 필요한 예측·분석 → 3D 비교 → 근거와 후속 질문 보고**를 웹에서 수행하는 해커톤 데모를 만든다. 분석이 어려운 경우에도 이유와 미완료 범위를 확인할 수 있어야 한다.

| 구분 | 현재 기준 |
|---|---|
| 기존 문서의 확정 범위 | HER2와 항체 후보 2–3개, 구조·근거 비교, 후속 확인 목록, 입력부터 보고까지 전체 흐름 |
| 사용자 지정 | 웹 호스팅 서비스, Docker 사용; AWS는 우선 검토하는 호스팅 후보 |
| 추가 확인: 2026-09-25 | 해커톤 기간에만 운영하며 서버에서 에이전트를 실행한다. 사용자는 실행에 필요한 서버 성능을 고려하기를 원하며, 구체적인 예산 상한은 아직 제시하지 않았다. |
| 이번 설계에서 선택 | React 기반 화면, Python API와 별도 분석 실행부, 저장된 작업 상태 조회; 세부 구성은 ARCHITECTURE 참조 |
| 확인 대기 | 접근 대상, 예산, 허용 데이터와 보관 정책, 실제 데모 후보·분석 구간·과학적 판정 기준 |

여기서 기능 요구사항과 화면 구성은 INTENT를 구체화한 설계다. 실제 연구자 수요나 효과가 검증되었다는 뜻은 아니다.

## 2. 사용자와 사용 흐름

업무 사용자는 항체 후보와 보유 자료를 비교하려는 연구자다. 현재 직접 전달 대상은 전체 동작과 판단 근거를 확인할 해커톤 심사위원이며, 실사용 조직·사용 빈도·동시 사용자 수는 확정하지 않았다.

1. HER2와 후보 서열, 선택적인 구조·관련 자료를 입력한다.
2. 후보·분석 구간·자료 대응을 확인하고 오류나 누락 안내를 확인한다.
3. 분석을 실행하고 단계별 진행 상태, 생략·보류·실패 이유를 확인한다.
4. 후보와 구조 조건을 바꾸며 3D 구조와 근거표를 함께 검토한다.
5. 검토 의견, 남은 질문, 출처를 확인하고 결과를 내려받는다.

## 3. 입력과 결과의 범위

| 항목 | 기능 요구 |
|---|---|
| 표적 | HER2 식별자 또는 서열. 실제 분석 구간을 표시하고 전체 표적과 혼동하지 않게 한다. |
| 후보 | 서로 구분되는 후보 2–3개와 각 중쇄·경쇄 FASTA. 항체 형식과 입력 서열의 범위를 확인한다. |
| 선택 자료 | 보유한 실험·예측 구조, 당쇄·주변 구조·기존 결합 근거. 파일이 있다는 이유만으로 해당 후보의 근거로 채택하지 않는다. |
| 초기 구조 형식 | PDB·mmCIF 지원을 구현 기준으로 제안한다. 파일 크기·원자 수·허용 서열 길이는 대표 입력을 확인한 뒤 제한한다. |
| 결과 | 3D 비교, 후보별 근거표, 범위가 명시된 검토 의견, 후속 확인 목록, 출처·실행 기록, JSON·CSV 다운로드 |

관련 자료의 범용 문서 업로드·자동 논문 해석 기능은 추가하지 않는다. 당쇄·주변 구조는 확보한 구조와 출처를 연결하는 범위이며, 없는 구조를 자동 생성한다고 약속하지 않는다.

## 4. 필수 기능과 완료 조건

아래 F01–F10은 전체 데모에 필요한 기능이다. 개발 순서는 의존성에 따라 정하며 일부만 구현한 상태를 전체 완료로 표시하지 않는다.

| ID | 기능 | 관찰 가능한 완료 조건 |
|---|---|---|
| F01 | 입력과 후보 식별 | 표적·후보 수·필수 서열을 확인하고 잘못된 필드와 이유를 표시한다. 입력 수정 후에는 이전 분석 결과와 섞이지 않는 새 검토를 만든다. |
| F02 | 자료 대응과 출처 확인 | 서열·사슬·잔기 번호·분석 구간의 대응과 누락을 표시한다. 불일치 후보는 해당 비교를 진행하지 않고 정정할 내용을 제시한다. |
| F03 | 필요한 분석 선택 | 기존 실험 구조로 충분하면 예측을 생략하고 이유를 남긴다. 부족한 경우 필요한 예측·분석을 수행하며 실제 사용한 자료·설정·실행 상태를 기록한다. |
| F04 | 진행 상태와 복구 안내 | 대기·실행·종료 상태와 현재 단계를 보여준다. 새로고침 후 같은 작업을 조회할 수 있고, 통신 단절·분석 실패·과학적 판단 보류를 구분한다. |
| F05 | 후보별 구조 검토 | 접촉·표면 노출·충돌·구조 신뢰도·자세 일관성을 근거와 함께 제시한다. 계산할 수 없는 값은 이유가 있는 미확인으로 표시한다. |
| F06 | 구조 조건 비교 | 같은 후보의 HER2–항체 중심 조건과 확보한 당쇄·주변 구조 포함 조건을 구분한다. 바뀐 판단의 위치·이유를 표시하고 자료가 부족한 조건은 비교 불가로 남긴다. |
| F07 | 3D와 근거표 연결 | 후보·조건·구조를 선택할 수 있다. 근거 항목을 선택하면 대응하는 사슬·잔기를 강조하며, 화면의 선택 대상과 표의 후보·조건이 일치한다. 누락 위치에 임의 좌표를 표시하지 않는다. |
| F08 | 검토 의견과 후속 질문 | 후보별·판단 항목별로 후속 실험 검토 가능 / 추가 확인 / 보류를 제시한다. 근거·적용 범위·반대 근거·필요 자료와 남은 질문을 함께 보여준다. |
| F09 | 결과 보고와 다운로드 | 화면·보고서·JSON·CSV가 동일한 분석 실행과 결과 버전을 가리킨다. 출처와 실행 상태를 확인할 수 있고, 파일에는 미확인·보류·실패 정보도 보존된다. |
| F10 | 부분 결과와 실패 처리 | 한 후보의 문제로 다른 후보의 유효 결과를 숨기지 않는다. 비교에 필요한 후보가 부족하면 전체 비교 미완료를 명시하고, 외부 호출 실패를 생물학적 부적합 판정으로 바꾸지 않는다. |

검토 의견은 치료 효능·결합력 순위가 아니다. 단일 종합 점수와 자동 최우수 후보 선정은 제공하지 않는다.

## 5. 화면 구성

| 화면 | 사용자가 확인하거나 수행할 일 |
|---|---|
| 검토 입력 | 표적·후보·보유 자료 입력, 입력 오류 확인, 분석 시작 |
| 분석 진행 | 후보별 현재 단계와 실행 상태, 자료 보완·생략·실패 이유 확인 |
| 비교 작업 화면 | 후보·구조 조건 선택, 3D와 근거표 연결, 근거 종류·누락·충돌 확인 |
| 결과 보고 | 검토 의견·후속 질문·출처 확인, JSON·CSV 다운로드 |

데스크톱 브라우저에서 전체 흐름을 우선 구현한다. 좁은 화면에서는 패널을 순서대로 배치하고 결과 텍스트·표가 잘리지 않도록 한다. 모바일에서 데스크톱과 같은 다중 3D 성능을 보장하는 것은 초기 완료 조건에 포함하지 않는다. 이는 이번 화면 설계의 기준이며 별도의 사용자 기기 요구를 확인한 결과는 아니다.

## 6. 공통 품질 요구

- **근거 일관성:** 모든 판단은 후보·구조 조건·출처를 식별할 수 있어야 한다. 실험 사실 / 계산 결과 / 미확인을 텍스트로 구분하고 색상만으로 의미를 전달하지 않는다.
- **지속성:** 브라우저를 닫아도 접수된 작업과 결과가 사라지지 않는다. 서버 중단 시 자동 성공이나 무조건 재실행 대신 중단 상태와 확인 가능한 결과를 남긴다.
- **사용성:** 3D 로딩·오류를 별도로 표시하며 3D 표시가 실패해도 근거표·보고서는 열람할 수 있다. 입력·후보 선택·보고서 탐색은 키보드로 조작할 수 있게 한다.
- **웹 제공:** HTTPS로 제공하고 외부 API 비밀키를 브라우저에 전달하지 않는다. 승인된 접근 범위가 파일·API에도 동일하게 적용되어야 한다.
- **실행 제한:** 작업 수·입력 크기·호출 횟수·시간 한도를 설정할 수 있어야 한다. 구체적인 상한과 응답 시간 목표는 실제 입력·계정·예산 확인 후 정하며, 대기 시간을 추정 근거 없는 완료율로 표시하지 않는다.

## 7. 검증과 완료 판단

| 검증 묶음 | 확인할 증거 |
|---|---|
| 정상 전체 흐름 | 후보 2–3개의 입력부터 F01–F10에 해당하는 화면·결과 파일까지 이어지는 실제 실행 기록 |
| 분석 분기 | 기존 구조로 예측을 생략한 사례와 실제 새 복합체 예측을 호출·비교한 사례 각각의 입력·설정·결과 |
| 불확실성 | 사슬·번호 불일치, 당쇄 자료 누락, 예측 불일치·지표 충돌에서 판단 범위와 보류 이유가 유지되는지 |
| 장애와 지속성 | 외부 호출 오류·timeout, 새로고침, API·worker 재시작에서 중복 실행·거짓 성공 없이 상태와 부분 결과를 확인하는지 |
| 표시 일치 | 선택한 근거의 잔기·후보·조건이 3D와 일치하며 보고서·다운로드에서도 같은 결과 버전을 사용하는지 |
| 호스팅 | 선택한 AWS 구성에 Docker로 배치한 후 실제 접근 범위·HTTPS·재접속·결과 다운로드가 동작하는지 |

공개 구조 1N8Z·1S78은 기존 [검증 문서](topics/her2/validation.md)의 참고 입력이며, 실제 사슬·서열·잔기 대응 확인을 대체하지 않는다. 과학적 기대값은 검토한 원자료에서 독립적으로 정하고 구현 출력으로 정답을 만들지 않는다. 합성 오류 입력과 저장된 이전 실행은 각각 합성·이전 실행으로 표시한다.

현재 통과한 제품 검증은 없다. 모델 정확도·실험 절감·연구 유용성은 위 기능 완료와 별도로 평가한다.

## 8. 미결정 항목과 결정 시점

| ID | 확인할 내용 | 담당·시점 | 미결정 시 영향 |
|---|---|---|---|
| Q01 | 팀·심사위원 제한 공개 / 예시만 공개 / 누구나 분석 실행 중 접근 범위 | 사용자 인터뷰, 인증·공개 설정 구현 전 | 인증과 실행 권한을 최종 확정할 수 없음 |
| Q02 | 해커톤 기간만 운영하는 것으로 확인. 남은 항목은 정확한 가동 날짜·시간, 총예산 상한, 사용 가능한 계정·도메인 | 사용자 인터뷰 일부 반영, 자원 생성 전 비용 산정 | EC2 사양의 검증 후보는 정하되 최종 규격·리전·실행 상한·호스팅은 미확정 |
| Q03 | 공개 예제만 쓸지, 비공개 서열도 받을지, 보관·삭제 기간 | 사용자 인터뷰, 입력 저장·외부 전송 구현 전 | 데이터 정책·외부 서비스 전송 범위 확정 불가 |
| Q04 | 실제 후보·항체 형식·분석 구간·구조 파일·허용 입력 크기 | 분석 담당의 자료 대조 후 팀 확인, 분석 구현 전 | 과학적 비교 범위와 기준 입력 미확정 |
| Q05 | 접촉·충돌·정렬 등의 정의·임계값·독립 기대값과 의견 판정 규칙 | 분석 담당의 출처 검토·검증, 판정 기능 구현 전 | 임의 수치로 후보 판정을 구현할 수 없음 |
| Q06 | 모델·계정 접근·응답 시간·호출 조건·라이선스와 실행 한도 | 실제 환경 확인, 통합·배포 전 | 예측 경로와 시간·비용 목표 미확정 |

Q02는 단기 운영 의도를 확인한 상태이며 예산 무제한을 뜻하지 않는다. Q01·Q03과 Q02의 나머지 항목은 확인 대기다. 나머지는 기존 [구현 전 미정 항목](topics/her2/validation.md#구현-전에-정할-항목)을 이어받았으며, 조사·실행으로 확인할 내용을 사용자 추측으로 대신 채우지 않는다.

## 9. 제외 범위

새 항체 생성·추가 학습·임상 판단·효능 순위·실험 프로토콜 자동 확정은 [INTENT](intent/INTENT.md)의 범위 밖이다. 결제·조직 관리·실시간 공동 편집·다중 서버 자동 확장·별도 PDF 보고서 제작도 초기 데모의 필수 기능에 추가하지 않는다.

## 10. MVP 이후 고려 사항

기존 후보 입력 → 분석 → 3D 비교 → 결과 보고까지 현재 MVP를 먼저 완성한다. 신규 항체 생성은 이후 확장 후보로 두고, 생성 도구의 실제 실행 가능성·소요 시간·비용과 생성 결과를 기존 비교·검토 흐름에 연결할 수 있는지 확인한 뒤 도입 여부를 결정한다. 현재 MVP의 필수 기능이나 완료 조건에는 포함하지 않는다.
