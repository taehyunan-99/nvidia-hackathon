# INTENT — HER2 항체 후보 검토 에이전트

작성일: 2026-09-25. 상태: 기존 HER2 문서에 근거한 초안.

## 1. 목적

**HER2 항체 후보를 검토하는 연구자가 후보별 구조 근거와 불확실성을 비교하고, 다음 실험에서 무엇을 확인할지 판단하도록 돕는다.**

후보마다 흩어져 있는 서열·구조·결합 가설을 하나의 검토 흐름으로 연결한다. 각 후보에 대해 어디까지 판단할 수 있는지, 판단을 막는 정보는 무엇인지, 후속 확인이 필요한 이유는 무엇인지를 함께 제시한다.

현재 프로젝트의 직접 목표는 이 과정을 입력부터 3D 비교·결과 보고까지 보여주는 해커톤 데모다. 연구자의 항체 후보 비교를 업무 시나리오로 삼으며, 실제 사용 조직이나 현장 효용이 확인된 운영 서비스로 전제하지 않는다.

근거: [프로젝트 개요 — 목적과 해결하려는 문제](../topics/her2/overview.md).

## 2. 해결하려는 문제

후보마다 보유한 서열과 구조, 결합 가설, 근거 수준이 다르면 같은 기준으로 비교하기 어렵다. 구조가 있어도 그 자료가 해당 후보와 분석 구간을 제대로 나타내는지, 필요한 주변 정보가 빠져 있지는 않은지 확인해야 한다.

비교 결과만으로 다음 실험을 결정하기도 어렵다. 연구자는 후보 간 차이뿐 아니라 그 차이를 뒷받침하는 근거, 아직 판단할 수 없는 부분, 추가로 확보해야 할 자료를 함께 알아야 한다.

이 프로젝트가 다루는 문제는 **후보별 근거와 정보 공백이 연결되지 않아, 후속 실험에서 확인할 질문을 정리하기 어려운 상태**다. 이 문제 정의는 현재 프로젝트 문서에 기반하며, 사용자 인터뷰나 현장 관찰로 검증된 사실을 뜻하지 않는다.

근거: [프로젝트 개요 — 해결하려는 문제](../topics/her2/overview.md#해결하려는-문제).

## 3. 사용자가 얻어야 할 변화

검토를 마친 사용자가 다음을 설명할 수 있도록 한다.

- **후보별 차이:** 결합 부위와 접근성, 구조상 우려가 어디에서 어떻게 다른지.
- **판단의 근거와 범위:** 실험에서 확인한 사실, 계산으로 얻은 결과, 미확인 항목이 각각 무엇인지.
- **판단이 달라지는 조건:** 확보한 당쇄·주변 구조를 포함했을 때 검토 의견이 달라지는 위치와 이유가 무엇인지.
- **다음 확인 과제:** 후속 실험 검토가 가능한 부분, 추가 확인하거나 보류할 부분, 이를 해소하기 위해 필요한 자료와 질문이 무엇인지.

이 변화는 제품이 제공하려는 가치다. 실험 횟수·비용·검토 시간의 절감이나 새로운 후보에 대한 예측 정확도가 입증됐다는 의미는 아니다.

근거: [프로젝트 개요 — 제공할 결과와 비교 관점](../topics/her2/overview.md#제공할-결과), [검증 기준 — 데모 동작과 연구 유용성의 구분](../topics/her2/validation.md#데모-동작과-연구-유용성의-구분).

## 4. 기능적 범위와 경험

검토 대상은 **HER2와 항체 후보 2–3개**이며, HER2 세포외 영역과 항체의 항원 결합 부위를 중심으로 살펴본다. 사용자는 표적·후보 서열과 보유 자료를 제공하고, 서비스는 자료 확인부터 필요한 분석, 비교, 검토 의견까지 연결한다.

### 자료 상태에 맞춰 검토한다

보유 자료가 후보와 맞는지, 비교에 필요한 정보가 충분한지 확인한다. 기존 자료로 판단할 수 있는 부분은 활용하고, 부족한 부분은 필요한 예측·분석이나 자료 보완으로 연결한다. 입력이 맞지 않거나 근거가 부족한 부분은 판단을 보류하고 이유를 알린다.

### 구조와 근거를 함께 비교한다

사용자가 3D 구조와 후보별 비교 내용을 통해 결합 부위·접촉 위치·접근성·구조상 문제를 확인하도록 한다. 같은 후보에 대해 HER2–항체 중심 구조와 확보한 당쇄·주변 구조를 포함한 조건을 비교하여, 추가된 구조 조건이 검토 의견에 미치는 영향을 보여준다.

### 다음 검토로 이어지는 결과를 제공한다

후보별로 후속 실험 검토 가능·추가 확인·보류 의견과 그 적용 범위·이유를 제시한다. 의견을 사용한 자료와 출처에 연결하고, 남은 질문과 필요한 후속 확인 항목을 함께 정리한다. 사용자가 검토 의견의 근거를 되짚을 수 있어야 한다.

근거: [프로젝트 개요 — 입력과 산출물](../topics/her2/overview.md), [에이전트 설계 — 자료 상태에 따른 판단 분기](../topics/her2/agent-design.md#단계가-고정-파이프라인이-되지-않게-할-분기).

## 5. 지켜야 할 경계

- **근거의 종류를 구분한다.** 실험 사실·계산 결과·미확인을 섞지 않으며, 당쇄나 주변 구조 자료의 누락을 해당 구조가 없다는 뜻으로 해석하지 않는다.
- **불확실성을 결과에 남긴다.** 충돌하는 근거를 하나의 종합 점수로 숨기지 않는다. 판단 보류와 분석 미완료를 성공한 분석처럼 제시하지 않는다.
- **구조 검토의 범위 안에서 설명한다.** 구조 신뢰도와 계산 지표를 실제 결합력·치료 효과·부작용 확률의 순위로 바꾸지 않는다. 분석한 부분 구조가 전체 항체나 실제 세포 환경을 자동으로 대변한다고 보지 않는다.
- **연구자의 후속 판단을 지원한다.** 새로운 항체 생성, 모델 추가 학습, 임상 판단은 현재 범위에 포함하지 않는다. 구체적인 실험 프로토콜과 판정값을 정하는 일도 이 문서에서 약속하지 않는다.

## 6. 후속 문서와의 경계

이 문서는 누구의 어떤 문제를 해결하고 어떤 기능적 가치를 제공할지 정한다. 아래 내용은 INTENT를 바탕으로 후속 문서에서 구체화한다.

| 문서 | 다룰 내용 |
|---|---|
| PRD | 세부 요구사항, 입력·출력 조건, 사용자 흐름, 우선순위와 기능별 완료 기준 |
| ARCHITECTURE | 시스템 구성, 구성요소의 책임, 데이터와 실행 흐름, 연동 구조 |
| ADR | 주요 결정의 배경, 고려한 대안, 선택 이유와 제약 |

실제 데모 후보와 분석 구간, 판정 기준, 실행 환경 등 기존 [미정 항목](../topics/her2/validation.md#구현-전에-정할-항목)은 이 초안에서 확정하지 않는다. 현재 문서에 없는 사용자 특성·현장 수요·효과 수치는 추정하여 채우지 않는다.
