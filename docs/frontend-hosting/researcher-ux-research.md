# 연구자 UX 조사와 화면 아이디어

조사일: 2026-09-25. 목적: HER2 항체 후보 2–3개를 검토하는 전문가에게 적합한 정보 구조를 찾는다. **조사에 기반한 UX 가설이다. 후속 사용자 요청으로 비교 화면의 A/B 시안을 구현했으며 전문가 검증 전이다.** 실제 대상 연구자를 인터뷰하거나 현재 시안을 사용성 평가한 기록은 없다.

## 우리 서비스에 대한 설계 가설

아래는 위 근거와 [프로젝트 목적](../topics/her2/overview.md)을 연결한 **제안**이다. 전문가가 직접 요구한 기능으로 기록하지 않는다.

| 연구자가 하려는 일 | UX 아이디어 | 우리 범위에서의 검증 |
|---|---|---|
| 후보 간 중요한 차이를 빠르게 파악 | 후보 2–3개를 열로, 검토 항목을 행으로 놓는 비교 요약. 각 값 옆에 근거 종류·미확인·보류 이유 표시 | 후보를 계속 전환하지 않고 차이와 비교 불가 항목을 설명할 수 있는가 |
| 같은 조건끼리 비교하는지 확인 | 표적 구간·항체 형식·구조 조건·출처/실험/예측 구분을 결과 상단에 유지 | 조건이 다른 두 값을 같은 기준으로 오해하지 않는가 |
| 우려가 생긴 위치를 직접 검토 | 근거 선택 → 해당 후보·조건·구조 위치로 연결, 좌표 있을 때만 잔기 강조 | 선택한 후보·조건·잔기가 표와 구조에서 일치하는가 |
| 의견을 검증하고 이견을 판단 | 이유·반대 근거·원출처·계산 정의를 상세 패널에 제공. 중요한 누락·보류는 접지 않음 | 설명을 신뢰하는 이유와 아직 판단할 수 없는 이유를 구분하는가 |
| 다음 검토로 이어가기 | 항목별 후속 질문과 관련 근거를 함께 보고, 동일 실행·설정 버전의 파일로 내보내기 | 검토 의견을 근거까지 추적할 수 있는가 |

## 제안하는 비교 작업 화면

상단에 `표적·분석 구간 / 실행 버전 / 선택한 구조 조건`을 고정하고, 먼저 작은 후보 비교 요약을 보여준다. 그 아래에 **3D·선택 근거 상세**를 나란히 배치한다. 비교 항목 선택은 아래 두 패널에 함께 반영한다. 상세 패널 안의 출처·실행 설정은 펼쳐 볼 수 있게 하되, 미확인·상충 근거·보류 요약은 첫 화면에서 보이게 한다.

기존 `입력 → 진행 → 비교 → 보고` 흐름은 유지 가능한 안이다. 입력은 누락·대응 확인, 진행은 실제 수행/생략/보류 이유, 비교는 관찰과 근거 검토, 보고는 후속 질문 정리에 집중한다. 처음 방문한 심사위원을 위한 소개 화면과 반복 검토자의 작업 화면은 정보 밀도를 다르게 둘 수 있지만 별도 연구자 모드를 바로 추가할 필요는 없다.

이 구조는 사용자에게 앞서 제안한 ‘3D 중심’ 배치를 세부 조정하는 제안이다. 사용자는 B의 쟁점 우선 방향과 비교 요약 아래 쟁점·3D를 나란히 배치하는 개선안에 동의했다. 실제 전문가에게 적합한지는 짧은 작업 평가로 확인한다. 후속 사용자 요청으로 기존 A안과 제안 B안을 화면에서 전환하는 시안을 구현했다. [화면 계획](screen-plan.md)의 후속 범위를 따른다.

## 우선순위와 범위

1. **우선 제안:** 후보를 동시에 보는 요약, 선택 문맥 유지, 보류·누락 상시 표시. 현재 계약의 Candidate·Condition·Evidence·Opinion에서 출발할 수 있다. 없는 지표 행을 실제 계산처럼 채우지 않는다.
2. **실제 구조 연결 후:** 근거·잔기·3D 연동과 조건 전환. 기준 구조·정렬 대응이 없으면 같은 시점의 비교나 정렬 완료를 약속하지 않는다. 당쇄 자료 누락은 ‘당쇄 없음’이 아니다.
3. **수요 확인 후:** 필터 이력·주석·탐색 저장. 임시 결과만 보관하는 현재 정책과 충돌할 수 있으므로 영구 프로젝트·협업·공유 기능을 추가하지 않는다. 항체 2–3개에 수백 후보용 필터·클러스터링은 과도하다.

NVIDIA 스타일의 녹색은 주요 조작에 사용한다. 후보 판정이나 구조의 신뢰도·사슬 색을 브랜드색으로 통일하지 않는다. 과학적 범례는 결과 의미에 맞게 별도로 표시해야 한다. 디자인의 단정함은 정보 숨기기가 아니라 동일 문맥에서 비교하는 데 사용한다.

## 사용자·전문가 인터뷰

사용자에게 우선 역할을 질문했다: 후보를 비교해 후속 실험을 검토하는 연구자 / 사슬·잔기·구조를 분석하는 전문가 / 둘 모두. 사용자는 주제 적합성을 물었고, 계산·구조생물학 연구자 또는 항체 엔지니어를 핵심 사용자로 두는 제안에 동의했다. 실제 대상 전문가의 선호 검증과는 구분한다.

실제 전문가를 만날 수 있으면 다음 세 질문을 실제 최근 작업 사례로 확인한다.

- 최근 후보 비교에서 무엇을 먼저 열었고, 비교를 멈추게 한 자료 부족이나 조건 차이는 무엇이었는가?
- 결과 의견을 받아들이기 전에 반드시 확인하는 원자료·설정·지표는 무엇인가?
- 다음 담당자나 실험 검토로 전달할 때 필요한 산출물은 무엇인가?

## 작은 사용성 평가안

실제 참여자 모집·연락은 아직 하지 않았다. 아래는 검증 계획이며 결과나 연구자 요구로 표현하지 않는다.

기존 모의 상태 중 자료 부족·과학적 보류·실행 실패를 구분하는 과제를 사용하고, 기존 후보 전환형 화면과 동시 비교 요약형 시안을 같은 정보로 비교한다. 참여 순서를 번갈아 학습 효과를 줄이고, 적은 수의 정성 평가에서 얻은 결과는 일반화하지 않는다.

- 과제: 조건이 다른 항목 찾기, 보류 이유와 출처 확인하기, 다음 확인 질문 찾기.
- 관찰: 완료 여부·소요 시간·후보 전환 횟수·잘못된 확신·질문한 내용. 수치는 평가 후 기록한다.
- 필수 오류 확인: 실패를 생물학적 부적합으로 오해하거나 누락을 0·없음으로 해석하는지, 좌표 없는 항목을 3D로 확인했다고 생각하는지.

현재 fixtures에는 실제 구조·출처가 없으므로 실제 구조 해석과 출처 추적의 유용성을 검증할 수 없다. 그 평가는 검토된 실제 입력·대응표·자료가 준비된 뒤 수행한다.

## 조작 방식의 추가 아이디어

2026-09-25 사용자 요청으로 기록한다. 사용자 동의는 제품 방향에 대한 동의이며 전문가 선호의 실증은 아니다.

| 아이디어 | 상호작용 | 근거 수준 | 우선순위·현재 상태 |
|---|---|---|---|
| 선택 한 번으로 연결 | 근거 선택 시 후보·조건·잔기·3D 위치·출처를 같은 문맥으로 표시 | RCSB의 서열↔3D 연동에서 착안. 출처까지 연결하는 구성은 우리 설계 가설 | 우선 적용. 후보·모의 근거 연결만 구현; 실제 잔기·3D·출처 연결은 미구현 |
| 기준 후보 고정 | A를 기준으로 두고 B·C를 바꾸어도 검토 항목·조건 유지 | 비교 작업을 구체화한 설계 가설; 해당 조작의 직접 사용자 선호 증거 없음 | 후속 검증. 미구현; 구조 정렬은 별도 검증 필요 |
| 탐색 되돌리기 | 직전 후보·조건·근거 선택으로 복귀. 상태 저장은 별도 검토 | 전문가 공동 설계 연구 §7의 필터 되돌리기·탐색 상태 저장 피드백 | 후속 검증. 미구현; 분석 재실행이나 영구 저장과 구분 |
| 미확인 → 다음 행동 | 미확인 표시를 누르면 빠진 자료·영향받는 판단·재검토 조건을 펼침 | 기존 근거·추적 요구와 프로젝트의 보류 경계를 연결한 설계 가설 | 우선 적용. 일반 후속 질문은 표시되지만 미확인 항목별 연결은 미구현 |

우선순위는 **선택 연동 + 미확인 항목의 다음 행동**이다. 빠진 자료와 재검토 조건은 제공된 근거·의견에 명시된 내용만 사용하고, 없는 경우 ‘검토 조건 미제공’으로 남긴다. 임의 실험 방법·판정 임계값을 생성하지 않는다. 실제 좌표가 없으면 잔기 강조가 작동한 것처럼 표현하지 않는다.

검증 과제는 ‘미확인 항목에서 필요한 자료와 영향받는 판단 찾기’, ‘근거를 바꾼 뒤 모든 패널의 후보·조건 일치 확인’, ‘직전 선택으로 돌아가기’다. 관찰 결과가 생기기 전 효율 향상이나 연구자 만족을 완료 사실로 기록하지 않는다.
