# 로컬 실제 E2E 확인

공개 배포 전에 사용자가 직접 확인하는 절차다. 로컬 통합 검사는 실제 공개 좌표를 계산했지만 NVIDIA 실호출을 대신하지 않는다. 테스트 대역을 제품 설정에 넣지 않는다. 현재 미커밋 변경을 포함한 checkout에서 이미지를 새로 빌드한다.

## 시작

1. `.env.example`을 **새** `.env.local-e2e`로 복사한다. 기존 개인 파일은 덮어쓰지 않는다. 임의 영숫자 DB 비밀번호와 비어 있는 WEB_PORT(예: 18095)를 지정한다.
2. `DATA_MODE=live`를 설정한다. 모델까지 확인하려면 `LOGIC_AGENT_MODE=nat`와 본인의 `NVIDIA_API_KEY`를 이 개인 파일에만 넣는다. 원격 키를 화면·보고서·Git에 붙여 넣지 않는다. `rule`도 키가 있으면 모델을 호출할 수 있다.
3. 저장소 루트에서 아래를 실행한다. 새 project 이름은 기존 개발 DB·볼륨과 분리한다.

```sh
docker compose -p her2-user-e2e --env-file .env.local-e2e config -q
docker compose -p her2-user-e2e --env-file .env.local-e2e up --build -d --wait
```

`http://127.0.0.1:<WEB_PORT>`로 접속한다. 화면에 모의 환경이라고 나오면 실제 분석 테스트를 시작하지 말고 API·worker의 DATA_MODE가 모두 live인지 확인한다. 기본 시나리오는 1N8Z 실험 구조 + 6BHZ 서열 기반 복합체 예측으로 Boltz 호출을 포함한다. 예측 없이 기존 두 실험 구조를 보려면 ‘실험 구조 비교’를 선택한다. NAT 판단은 별도 모델 호출이다. [세 시나리오와 검증 결과](test-data.md)를 따른다.

모델 호출 없이 로컬 기능만 먼저 확인할 때는 두 키(`NVIDIA_API_KEY`, `NGC_API_KEY`)를 비우고 `LOGIC_AGENT_MODE=rule`, `PDB_SEARCH_ENABLED=0`으로 실행한다. 이 결과를 모델 E2E 성공이라고 기록하지 않는다. NVIDIA 키가 없을 때 NAT가 규칙으로 복구한 경우도 모델 성공이 아니다.

2026-09-27 사용자 승인 범위는 [분석 검증 계약](../topics/her2/analysis-validation-contract.md)을 따른다. 자료가 없는 전체 접근성의 사유 있는 보류는 허용하지만 정식 충돌·복수 자세 계산의 미구현이나 실행 오류를 완료로 처리하지 않는다. API 이미지가 고정 버전 Reduce·Probe와 원자 사전을 포함하며, 예측은 2샘플을 요청해 각각 보존한다. 추가 구조의 정렬은 원본 파일을 바꾸지 않는다.

NVIDIA 실제 요청은 재시도 포함 실행당 Nemotron 40건·Boltz-2 4건으로 제한된다. `MODEL_BUDGET_PATH`를 지정하면 여러 실행이 같은 한도를 공유하므로 내부 검증 외의 사용자 테스트에서는 비워 둔다. 이 상한은 제공자의 계정 한도·무료 제공을 보증하지 않는다. NAT는 응답이 사고 토큰으로 소진되는 재현 오류를 피하도록 Nemotron의 `enable_thinking=false`를 명시하며 실제 도구 선택·실행 주체는 계속 기록한다.

## 확인할 흐름

| 사례 | 직접 확인할 결과 |
|---|---|
| 공개 테스트 데이터 | 새 실행 접수 → 실제 진행 → 실험 구조 재사용과 접촉·표면 근거 → 조건별 비교 → JSON·CSV 다운로드 |
| 근거·후보·조건 변경 | 선택한 근거의 관측 잔기만 강조되고 미확인 근거에는 이전 강조가 남지 않음. 후보와 출처가 함께 변경됨 |
| 실행 주소 | 주소의 `?run=...`로 새로고침·같은 브라우저의 새 탭에서 같은 결과 조회. 다른 브라우저/시크릿 창은 거부됨. URL은 공개 공유 링크가 아님 |
| 직접 입력·예측 | 실제 확인하려는 공개 후보의 서열·출처로 접수. 모델 호출·구조 검증·규칙 복구를 구분. 실패한 요청을 무조건 반복하지 않음 |
| 잘못된 입력 | 잘못된 표적·서열·출처가 다른 공개 후보 결과로 대체되지 않음 |
| 접수 한도 | 한 세션의 실행이 대기/진행 중이면 추가 접수 거부; 기존 실행은 유지. 동일 접수 키 재시도는 같은 실행 반환 |
| 실패·시간 제한 | 외부 실패·실행 제한이 생물학적 부적합이나 모델 성공으로 표시되지 않음 |
| 만료 | 마지막 정상 세션 연결 후 30분이 지나면 조회 불가. 열린 화면의 heartbeat는 만료를 연장하므로 탭을 닫은 뒤 확인. 파일·DB 입력/결과 정리 후 원래 결과가 재노출되지 않음 |

실모델 성공 확인에는 실제 모델의 도구 이벤트, 예측이 필요한 경우 Boltz 응답과 입력 대응·파일 검증, 규칙 복구 여부를 함께 본다. 단순히 `live`나 `completed`라는 표시만으로 판단하지 않는다. 새로운 항체의 과학적 예측 정확도는 실행 성공과 별도다.

## 검증용 기본 제한

- 세션당 대기·진행 1건, 전체 10건, 실제 분석 동시 1건, 실행 1200초.
- 유효 세션 100개, 세션당 저장 입력 10개, 변경 요청(heartbeat 포함) 전체 분당 120회. DB 카운터를 사용하며 API 인스턴스가 달라도 공유한다.
- 요청 전체 21 MiB, 파일당 20 MiB, 본문 수신 30초. API 프로세스당 본문을 받는 변경 요청은 1개이며 초과는 재시도 가능한 429다. 파싱 전에 chunked 본문도 검사한다.
- DB와 서비스 파일 합계 1 GiB는 접수·worker 실행 중 확인하는 **용량 경계값**이다. OS의 디스크 quota가 아니므로 쓰기 중 순간 초과가 가능하며, 임의 외부 모델 응답·다중 호스트에 대한 하드 디스크 보장을 뜻하지 않는다. 한도에 도달하면 새 작업을 받지 않고 실행 중 작업을 종료한다. 만료 자료 정리 후 실제 사용량을 확인한다.

환경변수 예시의 값을 바꾸고 컨테이너를 재생성하면 조정할 수 있다. 이 값들은 로컬 해커톤 검증용이며 실제 처리 시간·동시 사용자 성능의 보증이 아니다. 실제 모델 E2E에서 시간이 부족하면 해당 기록을 근거로 조정한다.

## 종료와 판정

`docker compose -p her2-user-e2e --env-file .env.local-e2e down`은 데이터를 보존한다. 입력·결과가 더 필요 없을 때만 이 **검사용 project**에 `down -v`를 사용한다. 기존 다른 project의 볼륨을 삭제하지 않는다.

확인한 입력·실행 ID·오류·모델 복구 여부·화면/다운로드 일치와 느린 구간을 기록한다. 사용자의 실제 E2E가 끝나기 전에는 AWS·공개 HTTPS·배포를 진행하지 않는다.

## 현재 로컬 서버와 남은 관문

2026-09-27 `http://127.0.0.1:18095`의 `her2-user-e2e`를 실행해 유지 중이다. 소개·팀 별도 worktree 작업과 분리되어 있고 해당 수정은 자동 반영되지 않는다. 도구 거부 반복을 상태별 요청 스키마와 반복 중단 조건으로 수정했다. 새 영속 실행에서 공개 구조·실제 예측·비교·보고가 도구 거부와 규칙 복구 없이 완료돼 사용자 직접 E2E를 시작할 수 있다. 사용자 직접 확인에서 근거 선택 드롭다운·결과 파일 영역·반복 배너·다시보기 제거·당시 직접 입력 두 후보 고정 피드백을 반영했다. 이후 세 시나리오 적용 중 최신 요청으로 직접 입력도 2–4개 추가·제거를 복원했다. 전체 최종 사용자 E2E 승인과 공개 배포는 남아 있다. 상세 근거와 호출 한도는 [최종 내부 검증](../topics/her2/analysis-validation-contract.md#도구-거부-반복-수정과-최종-내부-검증)을 따른다.

## 세 시나리오 반영 — 2026-09-27

첫 화면에 실험 구조 비교 / 실험 구조와 예측 비교(기본) / 예측과 계산 보류 확인을 제공한다. 같은 접수·진행·결과 저장 경로를 사용한다. MSA는 현재 미연결·기본 실행 제외이며 통제된 추가 검증 후 도입을 검토한다. 두 신규 시나리오의 실제 모델 검증, 입력·계산·보류·3D·파일·재조회 결과와 해석 한계는 [테스트 데이터 기록](test-data.md#이번-검증-상태)에 모았다.

검증은 `her2-scenario-validation`의 별도 DB/파일에서 수행했다. 새 승인 한도는 Nemotron 60·Boltz 4, 사용량은 24·2다. API 재시작과 별도 `her2-scenario-restore` 복원에서 두 결과 JSON·7개 구조 파일을 대조했다. 기존 `her2-user-e2e`는 실행 중/대기 작업이 없음을 확인한 뒤 검증된 API·worker·web 이미지로 교체했으며 기존 DB와 저장 파일은 유지한다. 개인 이미지 고정값은 `tmp/scenario-validation/user-images.json`; 사용자 서버에는 소진 여부와 무관하게 검증용 공유 계수를 연결하지 않는다.

현재 검증은 로컬 HTTP다. 이전 HTTPS 검증 이력을 이번 이미지의 공개 HTTPS·배포 완료로 확대하지 않는다. 사용자 최종 사용성 확인과 새 후보 정확도 평가 역시 별도다.

직접 입력의 후보 추가·제거 버튼은 입력칸과 같은 테두리 색을 사용하고 두 버튼 사이 12px 간격을 둔다. 최신 웹 이미지에서 실제 계산 스타일과 화면 배치를 확인했다.

최근 변경 후 점검에서 지연된 저장 응답이 입력 화면을 덮어쓰는 동작과 미측정 근거의 표시를 수정했다. 검증·모의/저장 응답 재사용 경계는 [후속 점검](runtime-audit.md#2026-09-27-최근-변경-후-점검)에 기록했으며 최신 로컬 이미지 고정값은 `tmp/post-update-audit/images.json`이다.

### 완료 후 조회량 개선

공개 배포 전에 프런트의 완료 후 반복 조회를 제거했다. 입력은 첫 조회에만 받고 진행 상태는 응답 완료 후 2초 간격으로 확인하며, 완료·부분 완료·실패·중단 후에는 세션 유지 요청만 1분 간격으로 보낸다. 결과 캐시는 화면 메모리 범위이며 새로고침·다른 실행 주소는 다시 조회한다. 세션 만료·접근 거부·다른 세션으로의 교체는 기존 결과 표시를 중단한다.

프런트 24개 검사·타입·빌드 통과. 모의 API를 연결한 실제 브라우저에서 3초 지연 응답에도 상태 요청이 겹치지 않고, 실행 상태 2회·입력 1회·결과 1회 후 1분 시점에 세션 유지 요청만 발생함을 확인했다. 새로고침 재조회와 다음 세션 유지 요청의 410 응답 뒤 결과 제거·만료 안내도 확인했다. 이번 확인에는 새 NVIDIA 호출이 없으며 AWS 부하 시험으로 해석하지 않는다. 새 프런트는 아직 위의 기존 Docker 이미지나 main에 반영되지 않았고, main 반영 후 배포 이미지를 다시 만든다. 개인 근거: `tmp/aws-https-deploy/polling-tests.log`, `polling-build.log`, `polling-browser-requests.jsonl`, `polling-browser-summary.json`.

### 공개 테스트의 일일 모델 호출 한도

2026-09-27 사용자 요청으로 전체 운영 기간 4회 제안을 철회하고, 공개 AWS 구성에 조정 가능한 일일 합계(Nemotron 4,000·Boltz-2 200)를 추가했다. 분석별 기존 40/4·동시 분석 1건·재시도 제한은 유지한다. 한국시간 날짜별 공유 계수는 worker 재시작에도 보존되고 다음 날짜는 새 한도를 사용한다. 검증용 기존 공유 계수와 별도이며 공급자의 실제 무료·속도 한도를 뜻하지 않는다. 새 실제 모델 호출 없이 동시 예약·일일 초과·날짜 변경·한도 조정·실행별 상한 보존과 재시도의 전송 전 차단을 검사했다.
