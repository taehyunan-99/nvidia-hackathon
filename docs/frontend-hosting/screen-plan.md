# 화면 구성과 임시 구현 범위

2026-09-25. 기존 [PRD](../PRD.md)의 네 기능을 유지하고, 사용자 동의에 따라 큰 타이포·간결한 조작·필요한 근거를 펼치는 구성을 먼저 구현한다. 화면 언어는 기존 문서의 한국어로 임시 표시하며, 브랜드명과 최종 언어 정책은 확정하지 않았다.

| 화면 | 배치·행동 | 임시 자료 연결 |
|---|---|---|
| 검토 입력 | 서비스 목적 한 줄, 모의 예제 시작, 접히는 직접 입력 UI | 예제는 fixtures.input 기준 후보. 직접 입력은 전송·분석하지 않고 별도 UI로 표시 |
| 분석 진행 | 후보별 단계 목록, 생략·보류·실패 이유, 결과 보기 | Run.candidates.steps, Run.error, result_available |
| 구조 비교 | 후보·조건 선택, 왼쪽 구조 영역, 오른쪽 펼치는 근거 | candidate_id → Condition → Evidence, gaps·measurement_state·reason |
| 결과 보고 | 후보별 검토 의견·후속 질문·해석 범위, 다운로드 상태 | Result.opinions·artifacts; mock 파일 다운로드 비활성화 |

## 상태와 이동

상단 단계 탐색으로 네 화면을 직접 볼 수 있다. 결과 없는 상태에서 비교·보고에 진입하면 진행 화면으로 안내한다. 미리보기 상태 선택기는 서비스 기능이 아닌 검토 도구로 표시한다.

| 시나리오 | 화면 처리 |
|---|---|
| queued / running | 후보별 대기·진행 단계, 결과 이동 비활성화 |
| completed | 모의 종료 표시, 실제 계산·구조·파일 미생성 설명 |
| scientific-hold | 의견의 보류·사유 보존, 실행 오류로 바꾸지 않음 |
| partial | 부분 결과 표시와 유효한 의견 유지 |
| failed / interrupted | 실행 실패·중단 구분, 결과 없는 경우 빈 상태, 자동 재실행 없음 |
| session-expired | 이전 결과 대신 만료 안내·새 검토 진입 |
| input-invalid | 오류 안내와 입력 화면 이동 |

3D 데이터가 없는 현재 모의 자료는 빈 구조 영역을 표시한다. 당쇄·주변 구조 조건에 자료가 없으면 비교 불가 이유를 표시하며 ‘당쇄가 없음’으로 표현하지 않는다. 실제 3D 로딩 실패·통신 장애는 연결부 구현 이후 검증한다.

## 구현·검증 경계

[frontend](../../frontend/README.md)는 React·TypeScript·Vite 기반의 로컬 화면 프로토타입이다. 기존 fixtures를 직접 사용하며 새 과학적 자료를 만들지 않는다. 서비스 API·Mol*·실제 구조·다운로드·세션·새로고침 복원·파일 업로드는 미연결이다. 직접 입력은 두 후보의 이름·필수 서열·공개 자료 체크 UI만 제공한다. 세 번째 후보 추가·입력 구간·출처·파일 검증은 후속 작업이다.

실행: `npm --prefix frontend install`, `npm --prefix frontend run dev`. 빌드: `npm --prefix frontend run build`. 임시 자료 검증은 기존 contracts/validate-contract.py를 사용한다. 제품 전체의 PRD 완료를 의미하지 않는다.

## 화면에서 비교하는 UX 제안

2026-09-25 사용자 요청으로 구조 비교 화면에 A/B 전환을 추가했다. `?view=compare`로 직접 열면 B 제안이 먼저 표시된다. A는 기존 구조·근거 패널, B는 동일 자료에 후보별 자료 준비 상태·검토 쟁점·다음 질문을 먼저 보여주고 기존 구조·근거 패널을 이어 배치한다.

- 전환 시 모의 시나리오·후보·구조 조건은 유지한다. 비교 대상은 데이터가 아니라 화면 구성이다.
- 후보와 쟁점을 선택하면 해당 후보의 의견·연결 근거·후속 질문과 기존 구조 패널의 후보 선택이 함께 바뀐다.
- 조건 기록과 실제 구조의 존재를 구분하며, 좌표·분석 구간이 없는 현재 fixtures에서는 비교 가능 여부를 확인 필요로 표시한다. 과학적 판정 자동화가 아니다.
- 현재 자료로 실제 조건 전후 변화나 상충하는 계산값을 만들지 않는다. 실물 결과 연결 후 해당 검토가 필요하다.

A/B 전환, 쟁점→후보·근거 연결, 조건 누락 시 이전 쟁점 제거, 보류·만료, 모바일 가로 넘침과 브라우저 오류를 검사한다.

## 후속 UX 방향 — 사용자 확인

B의 쟁점 우선 구조를 기준으로 다듬는다. 세로 길이를 줄이기 위해 비교 요약 아래 쟁점·선택 근거와 3D를 나란히 배치하고, 좁은 화면은 순서대로 배치한다. 아직 현재 시안에 적용되지 않은 후속 변경이다.

- 우선: 근거 선택의 후보·조건·잔기·출처 연동, 미확인 표시에서 빠진 자료·영향받는 판단·재검토 조건 열기.
- 후속: 기준 후보 고정, 직전 탐색으로 되돌리기. 영구 저장·협업 기능은 범위에 추가하지 않는다.
- 구현 상태·조사 근거·검증 경계는 [조작 방식 아이디어](researcher-ux-research.md#조작-방식의-추가-아이디어)를 따른다. 이번 업데이트는 문서 반영이며 해당 상호작용을 구현 완료로 표시하지 않는다.

## 최신 진입 구조 — 2026-09-25

사용자 요청으로 상위 메뉴를 분석·소개·팀으로 분리했다. 분석의 첫 화면은 예제 선택·서열 입력·검토 시작이며 자유 대화 UI는 제거했다. 기존 진행·비교·보고는 분석 내부에서 유지한다. 소개는 프로젝트 설명, 팀은 개인정보 없는 카드 3개와 사용자 확인된 GitHub 링크를 담는다. [조사와 표현 기준](bio-agent-experience.md)을 따른다.
