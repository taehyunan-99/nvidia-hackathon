# 사이트 테스트 데이터

확인일: 2026-09-27. 현재 서비스·로직 계약을 기준으로 선정했다. 목적은 처음 방문한 사용자가 자료 준비 없이 접촉 위치·실험 근거·미확인 사항을 확인하는 것이다.

## 선정과 출처

기본값은 **HER2–trastuzumab Fab(1N8Z)와 HER2–pertuzumab Fab(1S78)** 한 묶음이다. 현재 카탈로그에 원본·서열·접촉 선택이 모두 있고, 서로 다른 결합 부위를 비교할 수 있어 현재 에이전트에 가장 적합하다. 모든 HER2 데이터 중 생물학적으로 최적이라는 주장은 아니다.

| 대안 | 데이터 성격과 예상 결과 | 선택 |
|---|---|---|
| 1N8Z + 1S78 | 공개 X선 구조, 정확한 중쇄·경쇄 대응, 접촉 잔기·3D·출처·후속 질문 | 기본 시연 |
| Pertuzumab 단일 변이 | 합성 서열, Boltz-2 호출 필요, 예측 품질·시간·실패가 가변적 | 개발용 `prediction_demo`, 기본 제외 |
| 짧은 서열·문자 오류·서로 다른 항체 사슬 혼합 | 합성 오류, 보류·예측 실패·기존 후보의 부분 결과 보존 검사 | 자동 회귀 검사 전용 |

[RCSB 1N8Z](https://www.rcsb.org/structure/1N8Z)는 HER2–Herceptin Fab 복합체, 2.52 Å 실험 구조다. 연결된 원 논문은 막 인접 부위 결합을 보고한다. [RCSB 1S78](https://www.rcsb.org/structure/1S78)는 HER2–pertuzumab Fab 복합체, 3.25 Å 실험 구조이며 원 논문은 도메인 II 결합을 보고한다. 공식 entry와 원 논문 초록을 위 확인일에 대조했다. 해상도는 항체 성능 순위가 아니다.

## 에이전트 입력과 적용

- [공개 입력 JSON](fixtures/public-reference-input.json)은 `service.demo_input.public_reference_demo()`에서 생성한다. 결과나 시나리오 상태를 포함하지 않으며 `example_id=her2-public-reference-v1`로 직접 입력과 구분한다.
- 표적은 P04626 식별자와 1N8Z 기탁 HER2 607잔기(전체 UniProt의 23–629 구간), 후보는 기탁 Fab 전체 중쇄·경쇄다. 1N8Z 경쇄 A 214/중쇄 B 220, 1S78 경쇄 C 214/중쇄 D 226잔기를 사용한다. 원본 대응은 [A-01](../topics/her2/a01-reference-inputs.md)을 따른다.
- 기존 `experimental_demo`와 동일하게 입력 FASTA 자체가 잘린 표적이므로 `analysis_range=null`이다. A-01의 전체 UniProt 서열+23–629 범위 지정 입력과 구별한다. 현재 로직은 표적 범위를 엄밀히 적용한 A-02 계산으로 연결되지 않았으므로 공통 23–629 구간만 재계산했다고 표현하지 않는다.
- 구조 업로드 없이 현재 로직의 검증된 카탈로그를 사용한다. 1S78 원본에는 복합체 두 벌이 있지만 현재 비교 선택은 HER2 A·중쇄 D·경쇄 C다. 기탁 서열과 좌표 누락을 혼동하지 않는다.
- 첫 화면의 기본 선택은 테스트 데이터다. 직접 입력은 같은 검증 HER2 표적 서열을 자동 제공하고 후보 이름·중쇄·경쇄와 공개 자료 확인을 받는다. 현재 분석에 쓰지 않는 구조 업로드와 JSON 모의 시나리오 업로드는 화면에서 제공하지 않는다. 입력 전환 시 작성 중인 후보 서열을 보존한다.
- 저장형 화면은 직접 입력과 동일한 `/api/reviews`→`/runs`→결과 경로를 사용한다. `DATA_MODE=mock`이면 모의임을 명시하고 실제 계산으로 표시하지 않는다. 별도 동기 시연 화면도 `public-reference` preset으로 동일 입력을 생성한다.

재생성: 저장소 루트의 Python 환경에서 `public_reference_demo()`를 JSON 직렬화해 위 fixture에 저장한다. `service/tests/test_demo_input.py`가 배포 입력과 원본 기반 생성값의 일치를 검사한다. 구조가 바뀌면 기대 결과를 재검토해야 하며 검사만 통과시키려고 수치를 바꾸지 않는다.

## 기대 결과와 한계

실험 구조를 재사용하고 Boltz-2 예측을 생략한다. 현재의 4.5 Å 중원자 접촉 선택은 1N8Z 39개·1S78 56개이며 **표적과 항체 양쪽 잔기의 합**이다. 기존 `contacts.json`의 좌표·해시 검증과 별도의 `logic/tests/test_contacts.py` 계산 대조를 근거로 사용한다. 이 수치는 결합력이나 새 후보의 효능 예측이 아니다.

양 후보의 접촉 근거·연결된 출처와 잔기, 실험 구조 2개, 주변 당 조건의 자료 공백, 근거에 연결된 의견·한계·후속 질문을 확인한다. `atom_clash`와 `surface_exposure`는 현재 `not_run`, 값은 null이며 기본 의견은 추가 확인이다. 데이터 변경만으로 아직 연결되지 않은 계산을 제공할 수 없다. 완전한 당쇄·막 환경을 검증한 데이터가 아니다.

NAT 기본 모드는 Nemotron 호출이 필요할 수 있다. 공개 구조라서 모든 외부 호출이 무료·불필요하다는 뜻은 아니다. 재현 가능한 자동 검사는 규칙 모드와 외부 호출 대역을 사용하며 실제 모델의 문장 품질은 별도다. 키·모델 장애는 기존 규칙 마무리/실패 표시를 유지한다.

## 검증

`service/tests/test_demo_input.py`: 배포 입력 출처 일치, 두 후보의 접촉·구조·한계·후속 질문, 합성 짧은 서열·잘못된 문자·사슬 혼합이 공개 근거를 잘못 물려받지 않는지 검사한다. 사슬 혼합의 외부 예측 실패는 대역으로 재현한다.

`service/tests/test_live.py`: 배포 fixture를 실제 영속 접수에 넣고 example_id 보존, worker 완료, 재접속 결과, 파일 무결성·소유권을 검사한다. PostgreSQL 검사는 반드시 폐기 가능한 별도 DB를 사용한다. 공개 배포와 실제 NVIDIA 모델 호출은 이 자동 검사에 포함하지 않는다.

## 소개 화면의 전달 순서

현재 사용자는 준비된 입력으로 서비스를 처음 평가하는 사람이다. 첫 선택에는 서열·해상도보다 비교 질문, 두 항체의 차이, 볼 수 있는 결과, 실행 여부가 필요하다고 판단했다. 사용자 인터뷰로 검증한 사용성 결론은 아니다.

상단 입력 방식 → 비교 질문 → 결합 부위가 다른 후보 카드 → 결과에서 볼 세 가지 내용 → 해석 범위 → 시작 버튼 순서다. 출처는 각 후보 바로 아래 제공하고, 해상도·기탁 서열 범위·미연결 계산은 펼침 항목에 둔다. 임의 점수·예상 우승 후보·근거 없는 소요 시간은 넣지 않는다. 결과 화면의 지표를 미리 완료된 결과처럼 제시하지 않는다.

### 이번 실행 결과

- 자동 검사: 입력 관련 5개 통과. 서비스·로직 검사 첫 실행 163개 통과·2개 외부 호출 검사 생략, 새 저장 입력 검사의 응답 필드 오류 1개 수정 후 해당 파일 6개 통과·1개 외부 예측 검사 생략. 계약 9개 시나리오·9개 오류 변형, 프런트 빌드 통과.
- 별도 폐기용 PostgreSQL과 로컬 API·worker에서 브라우저 버튼으로 NAT 실행 `run-377387c1cadc492f860693d4d8554b4a`를 접수했다. Nemotron의 두 후보 실험 구조 선택·의견을 확인했고, 두 후보 완료·접촉 39/56·구조 2건·한계·후속 질문이 저장되었다. Boltz-2 예측은 생략했다. 실제 모델 의견은 이번 실행에서 둘 다 후속 실험 검토 가능이며, 고정 정답으로 저장하지 않는다.
- 브라우저의 직접 입력 전환·입력값 보존·JSON 업로드 제거·결과 비교·보고·재접속 복원을 확인했다. 390px에서 가로 넘침이 없고 후보 카드가 세로로 배치되는 것을 확인했다. 라이트·다크, 키보드·마우스 전환을 점검하고 기본 뷰포트·라이트로 복원했다.
