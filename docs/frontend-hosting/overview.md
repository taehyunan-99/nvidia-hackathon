# 프런트엔드·호스팅을 위한 에이전트 조사

조사일: 2026-09-25. 기준 커밋: `c6945e61c58ff20a79814d64538889d599d6976b`. 작업 브랜치: `docs/frontend-hosting-plan`.

2026-09-26 갱신: 아래 조사 결과는 당시 기록이다. 현재 서비스 구현·실행 경로·검사 명령은 [서비스 가이드](AGENTS.md), 이번 담당 범위 확인은 [추가 인터뷰](#2026-09-26-서비스-범위-update)를 따른다.

## 목적과 읽는 순서

분석 로직이 완성되기 전에 서비스 담당자가 **무엇을 입력받고, 어떤 상태를 보여주며, 어떤 결과·파일을 저장하고 연결해야 하는지** 확인한다. 실제 로직의 형식·분석 수치·호스팅 요구량을 추측한 사실로 기록하지 않는다. 후속 사용자 요청에 따라 [임시 서비스 규격 v0.1.0](temporary-contract.md)을 먼저 정했으며 실제 로직과 adapter로 연결한다.

| 문서 | 답하는 질문 |
|---|---|
| [에이전트 로직](agent-logic.md) | 어떤 자료 상태에서 실행·생략·보류가 갈리며 무엇이 남는가? |
| [프런트 연동 요구](frontend-contract.md) | 화면별로 어떤 데이터가 필요하고 3D·표·진행 상태를 어떻게 연결하는가? |

| [임시 입출력 규격](temporary-contract.md) | 로직 완성 전에 어떤 필드·응답·예시로 서비스 작업을 시작하는가? |

프로젝트 목적은 [HER2 개요](../topics/her2/overview.md), 기능 완료 기준은 [PRD](../PRD.md), 기술 선택은 [ARCHITECTURE](../ARCHITECTURE.md)·[ADR](../ADR.md)이 원본이다. 이 조사는 [실행 계획 S-01·G1](../plan.md)의 서비스 소비 요구를 구체화한다. S-01의 실제 Mol*·Docker 실험까지 완료한 기록은 아니다.

외부 문서의 지원 기능은 우리 계정·입력에서의 성공을 뜻하지 않는다. 본문에서 **기존 설계 / 이번에 관찰한 사실 / 임시 서비스 계약 / 실제 로직과 검토할 항목**을 구분한다. 후속 임시 규격의 키·타입·enum은 개발 기준으로 사용할 수 있으며 최종 로직 규격을 의미하지 않는다.

## 이번 사용자 인터뷰

### 2026-09-26 서비스 범위 update

사용자는 프런트엔드·백엔드·호스팅만 갱신하도록 범위를 정하고, 제시한 세 방향을 코드·설계와 다시 대조해 맞으면 적용하도록 요청했다. ARCHITECTURE의 화면·API·worker 책임, ADR-003·007, 현재 소스를 대조하여 다음 기준을 반영했다.

- 프런트: 입력·진행·비교·보고와 3D 표시를 담당하며 로직의 분석값·판정을 소비한다.
- 백엔드: 영속 API·세션·파일 접근과 worker 운영을 담당한다. 분석 판단·도구 선택은 로직 담당이며, 별도 동기 시연 API와 mock 전용 영속 경로를 구분한다.
- 호스팅: 로컬 Compose·CI 정의는 구현 사실로 기록하고, 실제 분석의 영속 연결·공개 AWS 배포·CD는 완료로 기록하지 않는다.

9개 update 유형을 점검했다. 파일·명령 추가와 조사 가이드의 역할 보완을 반영하고, 기존 React·Mol*·FastAPI·PostgreSQL 선택을 유지했다. 삭제·이전 확인 대상과 반복 수정에 따른 학습 메모 후보는 없었으며 학습 기록은 변경하지 않았다. 코드별 가이드 분리는 별도 영역 재구성에서 검토할 수 있으나 이번에는 기존 가이드의 참조만 보완했다. 아래 2026-09-25 기록은 당시 조사 사실이며 현재 서비스 구현 부재를 뜻하지 않는다.

서비스 범위의 6개 교차 검사(컨벤션, 참조 경로, 금지·권장 충돌, 용어, 의존 방향, 명령)를 수행했다. mock 영속 경로와 실제 분석 시연 경로, worker 운영과 분석 책임을 구분하고 상위 문서 지도의 오래된 서비스 상태·명령을 수정했다. CI와 Docker의 런타임 버전 차이는 현재 사실로 명시했으며 버전 통일은 수행하지 않았다. 이 갱신 범위에 미해소 결정 충돌은 없다. 다른 담당 영역의 가이드 갱신은 포함하지 않는다.

### 2026-09-26 AWS 연결과 리전 결정

개인 AWS 계정의 IAM 사용자로 콘솔 로그인과 로컬 CLI 인증을 완료했다. 사용자 요청으로 배포 준비 리전과 CLI 기본 리전을 서울(`ap-northeast-2`)로 정했다. 별도 로컬 프로필 `her2-dev`에서 사용자 일치와 EC2 조회를 확인했으며 서울의 인스턴스 조회 결과는 0건이었다. 실제 자원 생성·공개 배포는 실행하지 않았다. 후속 사용자 결정은 약 한 달간 크레딧 차감 전 DB·CI/CD·AWS 서버 등 총 10만 원 이내이며, 도메인 없이 우선 준비한다. 추가 사용자 결정으로 4GB 서버를 잠정 기준으로 채택하고, 실제 에이전트·API·DB·웹을 연결한 서버에서 활성 분석 1건 조건으로 재검증한 뒤 최종 규격을 확정한다. 정확한 운영 날짜와 배포 권한은 별도 확인이 필요하다. 외부 AI 호출이 유료이면 총예산 잔여분에서 산정하고 무료로 가정하지 않는다.

## 디자인 인터뷰와 임시 화면 — 2026-09-25

사용자는 기존 화면의 딱딱함을 줄이고 깔끔하고 심플하면서 트렌디한 화려함을 요청했다. 밝은 바탕·큰 타이포·3D 중심 구성·은은한 청록과 블루 그라데이션을 제안했고 “응 일단 그렇게 해보자”로 임시 구현에 동의했다. [디자인 기준](design-guide.md)과 [화면 계획](screen-plan.md)에 반영했다. 후속 사용자 요청으로 [NVIDIA 디자인 조사](nvidia-design-research.md)를 수행하고 녹색 CTA·중립색 패널·Inter 영문 폰트를 적용했다. 한국어 화면은 임시이며 이름·최종 언어는 확정하지 않았다.

## 연구자 UX 조사 — 2026-09-25

사용자 요청으로 전문가 공동 설계 연구·RCSB 공식 UX·항체 연구 데이터 흐름 문헌을 확인했다. [연구자 UX 조사](researcher-ux-research.md)에 근거 수준, 동시 비교 요약→구조·근거 탐색 가설, 역할 인터뷰와 평가안을 정리했다. 실제 대상 연구자 인터뷰·사용성 평가는 아직 하지 않았다. 이후 사용자는 구조 검토 전문가를 핵심 사용자로 두는 방향에 동의했고, 사이트에서 비교할 수 있도록 요청하여 A/B 화면 시안을 추가했다.

사용자는 B의 쟁점 우선 구조와 비교 요약 아래 쟁점·3D 병렬 배치 방향에 동의했다. 추가 조작 아이디어도 문서에 반영하도록 요청하여 선택 연동·미확인에서 다음 행동을 우선, 기준 후보 고정·탐색 되돌리기를 후속 검증 항목으로 기록했다. 추가 동작은 구현 전이다.

사용자가 NVIDIA 한국 홈페이지를 원하는 시각 기준으로 지정하여 Elements와의 혼동을 정정했다. 공식 홈페이지를 직접 대조한 뒤 넓은 소개 비주얼·굵은 제목·#76B900 사각 CTA를 적용하고 분석 화면도 같은 스타일로 통일했다.

## 구현 전 3D·결과 표현 조사 — 2026-09-25

사용자는 구현에 앞서 3D 형식과 표현 방식을 이미지로 비교하고 이해하고 싶다고 요청했다. [3D 조사](3d-viewer.md)에 원본 mmCIF 확인, 동일 실험 좌표의 네 표현 이미지·회전 가능한 비교 자료, Mol* 연결 제안을 기록했다. 제품의 실제 뷰어 통합은 아직 수행하지 않았다.

추가로 사용자는 긴 텍스트에서 필요한 정보를 추리는 부담을 줄이고 시각적으로 표현 가능한 내용을 우선 보여주고 싶지만, 바이오 전문가의 검토 방식과 근거 요구를 먼저 조사하라고 요청했다. [별도 결과 표현 조사](result-presentation-research.md)에 전문가 연구·공식 도구·2025–2026 AI 사례를 구분하고, 비교 요약→선택한 시각 근거→상세 출처의 개선안을 제시했다. 사용자 선호는 확인됐으나 구체적 개선안의 채택·전문가 검증·제품 변경은 아직 없다.

후속 요청으로 출력 구조 개선을 승인하여 B안의 상태 비교표·선택 근거 통합·다음 확인 영역에 반영했다. [화면 계획](screen-plan.md)에 구현·검증 범위를 기록했다. 3D 표현 방식은 설명·선택 검토 단계이며 실제 Mol* 통합과 전문가 평가는 남아 있다.

## 분석 진행 시각화 — 2026-09-27 사용자 결정

중앙 에이전트가 실제 NVIDIA 스킬·자체 도구를 선택하고 작업하는 흐름을 시각적으로 보여준다. 텍스트는 선택 이유와 실행·검증·다음 행동에 필요한 만큼만 두고 상세 기록은 접는다. 고정 버전의 `boltz2-nim`을 연결하며, MSA-Search는 실제 입력에 대한 필요성이 확인되지 않아 연결하지 않는다. 실시간 분석에는 가짜 진행 지연을 넣지 않는다. 후속 사용자 요청으로 최대 4개 후보를 공통 그래프의 색상·번호 없는 동심원로 표시하고, 사용자가 저장 기록의 애니메이션만 다시 볼 수 있도록 한다. 다시 보기 버튼으로 한 번씩 재생하며 세부 제어는 두지 않는다. 재생은 실제 분석을 다시 호출하지 않는다.
