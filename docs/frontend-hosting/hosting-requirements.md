# 에이전트 흐름에서 도출되는 호스팅 요구

조사일: 2026-09-25. [ARCHITECTURE](../ARCHITECTURE.md)의 실행·저장 설계를 기준으로 필요한 인계와 검증을 정리한다. 실제 자원 생성·요금 산정·부하 측정은 수행하지 않았다.

후속 사용자 요청으로 [서비스 개발용 임시 규격 v0.1.0](temporary-contract.md)을 작성했다. 세션·입력·상태·파일 조회와 LogicRequest/ProgressUpdate/LogicOutput을 기준으로 mock API·worker·Docker 작업을 먼저 진행한다. 이 초기 계약은 실제 로직의 CPU·메모리 요구량이나 공급자 조건을 확정하지 않는다.

## 1. 어디에서 무엇이 실행되는가

| 위치 | 현재 설계의 책임 | 필요한 자원·의존성 | 확인 상태 |
|---|---|---|---|
| 사용자 PC 브라우저 | React 화면·Mol* 3D 표시, API 조회 | 브라우저 메모리·그래픽 성능·구조 다운로드 | PC 중심 사용자 확인. 실제 표시 성능 미측정 |
| web 컨테이너 | Vite 빌드 파일 제공, Caddy HTTPS·API 프록시 | 정적 파일·TLS 데이터·외부 진입점 | 설계 선택, 설정 없음 |
| api 컨테이너 | 입력 검증·접수·조회·파일 전달·접근 정책 | Python·FastAPI, DB·파일 저장소 연결 | 설계 선택, API 계약 미정 |
| worker 컨테이너 | 자료 대응·계산, NAT·Nemotron 연결, 필요한 MSA·Boltz 호출, 결과 조립 | Python·분석 패키지·시스템 의존성, CPU/RAM, 외부 통신·키 | 실행부 미구현, 실제 모델 제공 경로 재확인 필요 |
| db·파일 저장 | 허용 기간 내 작업·근거 참조와 원본·구조·결과 보존 | PostgreSQL, 현재 단일 호스트 영속 볼륨안 | 설계 선택/잠정안. 영속 볼륨도 임시 자료 만료 시 정리 필요 |
| 외부 서비스 | 공개 자료 응답·모델 추론 | 계정·엔드포인트·이용 조건·quota | 문서 조회만 완료, 계정 호출 미실행 |

서버의 GPU를 전제로 하지 않는 **외부 모델 호출 설계**와 모델 자체를 서버에 배치하는 방식은 다르다. 모델 제공 경로가 막혀도 자체 GPU 호스팅으로 자동 전환하지 않는다. 기존 4 vCPU·16 GiB 검증 후보는 최소 사양·충분한 사양·실측 요구량이 아니다.

## 2. 긴 실행과 공개 접근이 요구하는 운영

기존 설계는 한 worker가 검토 작업 하나씩 처리하고, 브라우저는 DB에 저장된 상태를 조회한다. 누구나 실행하는 공개 접근을 선택했다고 동시 분석이 무제한이 된 것은 아니다. 전체 접수량·대기 한도·사용자별 실행 제한·업로드 상한은 예산·API 한도·실측을 보고 정해야 한다. [사용자 인터뷰](overview.md), [기존 실행 상태](../ARCHITECTURE.md)

| 사건 | 서비스 운영부가 유지할 것 | 로직 담당에게 필요한 인계 |
|---|---|---|
| 브라우저 재접속 | 허용 보관 기간 내 기존 실행 조회, 중복 생성 방지 | 안정된 실행 ID·현재 단계·결과 참조 |
| API 재시작 | 이미 접수한 입력·작업의 유지 | API 요청 수명과 분리된 실행 진입점 |
| worker 중단 | 점유·생존 상태, interrupted 판정, 기존 결과 확인 | 마지막 단계·외부 요청 ID·산출물 상태 |
| 외부 요청 timeout | 성공 여부 불명확 표시, 무조건 재전송 방지 | 공급자별 요청 조회 가능성·오류·재시도 조건 |
| 결과 쓰기 중 종료 | 불완전 파일을 정상 산출물로 등록하지 않음 | 파일 완료 시점·해시·참조 등록 순서 |
| 삭제 기한 도래 | 조회·다운로드 권한 종료와 대상 데이터 정리 | 실행 중 삭제·외부 호출 중 삭제의 처리 경계 |

새로고침과 컨테이너 재시작 복구를 지원하려면 필요한 시간 동안 상태·산출물을 저장해야 한다. 단순 메모리 저장이나 브라우저 종료 이벤트만으로 복구와 삭제를 동시에 보장할 수 있다는 설계는 채택하지 않는다. 사용자는 공개 결과 목록 없이 본인만 임시 조회·다운로드하는 방식을 선택했다. 아래 4절의 서버 만료 초기안과 함께 구현 계약을 검토한다.

## 3. 외부 API에서 새로 확인한 제약

### Nemotron 제공 경로

기존 선택인 `nvidia/nemotron-3-nano-30b-a3b`의 공식 페이지를 2026-09-25 확인했을 때 **Free Endpoint: Deprecated**, **Partner Endpoint: Available**, **Download Available: Available**로 표시되었다. 이는 해당 무료 경로를 현재 사용 가능하다고 전제할 수 없다는 뜻이며, 기존 키의 호출 성공/실패를 직접 시험한 결과는 아니다. [Nemotron 공식 페이지](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b)

로직 담당은 실제로 이용할 제공자·모델 ID·엔드포인트·인증·NAT 호환성을 먼저 확인해야 한다. 파트너 제공자 채택이나 모델 교체는 비용·자료 처리 조건까지 비교한 뒤 결정한다. 이번 조사에서 대체 모델을 확정하지 않았다.

### Boltz-2 제공과 이용 조건

Boltz-2 공식 페이지는 개발용 무료 API의 rate limit·다른 이용자 트래픽에 따른 throttling 가능성을 안내하고, NVIDIA API Trial 약관을 연결한다. 무료 API 표시는 안정적인 처리량·우리 계정의 접근·공개 서비스 허용을 보장하지 않는다. [Boltz-2 공식 페이지](https://build.nvidia.com/mit/boltz2)

연결된 약관에서 확인한 항목은 다음과 같다. 이는 문구를 확인한 기록이며 계정별 계약·대회 허용 범위를 확정한 판단은 아니다.

| 약관 위치 | 확인한 내용 | 프로젝트에서 검토할 영향 |
|---|---|---|
| 1.2·1.4 | 제한된 시험 목적, 구독 전 내부 시험·평가와 production 이용 구분 | 누구나 실행하는 데모에 적용되는 대회 제공 조건·별도 허용·구독 필요 여부 확인 |
| 2.6(a) | 기밀 정보·민감 데이터 등의 입력 제한 | 결과 삭제만으로 비공개 서열 제출이 허용된다고 안내할 수 없음 |
| 2.3·2.4·3.3 | 세션 종료 후 보관의 원칙·예외, 데이터 수집·사용·보안 로그에 관한 조항 | 특정 API의 별도 고지와 실제 계약을 확인하고 외부 무보관을 약속하지 않음 |

출처: [NVIDIA API Trial Terms of Service](https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf). 특히 2.3의 세션 종료 문구만 떼어 무보관 보장으로 해석하지 않는다. Nemotron의 향후 파트너 계약에 이 약관을 자동 적용하지도 않는다.

## 4. 공개 자료 범위와 임시 결과 삭제

사용자는 검토 후 **이번 데모는 공개 자료만 허용**하기로 정했다. 직접 입력·업로드도 같은 범위이며, 비공개 서열·민감 자료 지원은 이후 별도 검토로 남긴다. 형식상 유효한 서열이라는 이유만으로 공개 자료임이 자동 검증되지는 않으므로 출처·안내·접수 정책을 구현 계약에서 구체화한다.

### 이탈·새로고침·삭제를 구분하는 초기안

사용자는 사이트 이탈 시 정리를 원하고 구체적 방식을 추천해 달라고 요청했다. **마지막 정상 세션 연결 후 30분 동안 재접속이 없으면 만료**시키는 방식을 제안한다. 30분은 공개 자료 데모에서 새로고침·일시적인 연결 끊김과 잔여 자료 정리를 절충한 설계값이며 실측된 최적값이나 확정 API 규격이 아니다. 분석 실행 시간 제한과도 별개다.

| 상황 | 초기 설계안 | 구현 전 검토할 경계 |
|---|---|---|
| 정상 이용·유예 내 재접속 | 유효한 세션 연결로 만료 시각 갱신, 같은 실행 조회 | 세션 식별·권한·갱신 간격과 여러 탭 처리 |
| 새로고침·탭 전환 | 그 이벤트만으로 즉시 삭제하지 않음 | 백그라운드 탭의 타이머 제한·연결 갱신 확인 |
| 사이트 이탈·강제 종료·네트워크 단절 | 종료 신호는 참고하되 신호 없이도 서버 유예 만료로 정리 | 브라우저 종료와 순간 단절을 완벽히 식별한다고 약속하지 않음 |
| 사용자의 명시적 종료·삭제 | 접근을 종료하고 안전하게 정리하는 동작을 검토 | 별도 종료 UI·API와 서버 확인 응답. 일반 페이지 이탈과 구분 |
| 만료 당시 대기·완료 작업 | 조회 차단 후 아직 시작하지 않은 작업과 임시 입력·결과 정리 | DB·파일 일관성, 정리 실패 재처리·기한 |
| 만료 당시 실행 중 작업 | 접근 종료와 삭제 대기 표시, 안전한 중단 지점 확인 후 파일 정리 | 처리 중 파일을 먼저 지우지 않음. 외부 진행 요청의 취소 가능성·완료 확인·추가 호출 중단 계약 필요 |

브라우저의 pagehide·unload 계열 이벤트는 항상 발생하지 않는다. sendBeacon의 반환값도 서버에서 삭제를 완료했다는 확인이 아니라 전송 대기열 접수 여부다. 따라서 **나가자마자 삭제 보장**이나 **30분째 물리적 삭제 완료 보장**으로 안내하지 않는다. 서버의 정리 주기·실행 중 처리·로그·백업까지 검증한 후 실제 삭제 기준을 확정한다. [MDN pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event), [MDN sendBeacon](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon)

### 삭제 대상과 이후 비공개 지원의 검토 범위

공개 자료 데모에서도 임시 결과를 남기지 않으려면 아래 저장 위치를 파악해야 한다. 향후 비공개 지원으로 확장할 때는 외부 전송·계약까지 다시 검토한다.

| 데이터가 머무는 곳 | 확인할 내용 |
|---|---|
| 브라우저 | 폼·viewer·다운로드·캐시·결과 접근 토큰의 수명, 공용 PC에서의 잔존 |
| API·worker 임시 영역 | 업로드·추출·MSA·예측 응답·구조·보고서 파일의 생성과 삭제 대상 |
| DB·파일 볼륨 | 입력·실행·근거·결과의 보관 기한, 삭제 실패 처리, 조회 권한 |
| 로그·NAT 추적 | 서열 원문·파일 내용·프롬프트·응답·접근 토큰이 기록되는지 |
| 백업 | 임시 민감 자료가 백업에 포함되는지, 복원으로 삭제 자료가 다시 노출되는지 |
| 외부 요청 | Boltz·MSA에 보내는 서열, LLM에 포함되는 근거·내용, 자료 검색 요청과 각각의 계약·보관 정책 |

특히 “예측 생략”은 “외부 전송 없음”을 의미하지 않는다. 자료 조회와 LLM 설명 단계에도 입력에서 나온 정보가 포함되는지 확인해야 한다. 인터넷에 누구나 접근할 수 있는 서비스와 개별 실행·파일을 누구나 읽을 수 있는 권한은 별도로 설계한다.

기존 영속 저장은 허용 보관 기간 내 재시작 복구를 뜻하도록 범위를 좁히며 영구 보관과 구분한다. 전체 임시 결과를 무조건 백업하는 정책은 채택하지 않고 백업 대상·만료·복원 후 접근을 함께 검토한다. [PRD Q03](../PRD.md)·[ADR-008](../ADR.md)에 사용자 결정과 이 초기안을 연결한다. UI의 삭제 버튼이나 결과 목록 비노출만으로 안전한 비공개 처리를 완료했다고 표시하지 않는다.

## 5. 로직 담당에게 받을 배포 인계 — D6 상세

| 받아야 할 실물·기록 | 호스팅에서 결정하는 것 |
|---|---|
| Python·NAT·Biopython·FreeSASA 등 정확한 버전, 시스템 라이브러리, CPU 아키텍처 | Docker 이미지·빌드 가능성·런타임 호환성 |
| 분석 진입 명령/함수·종료 동작, 진행·파일 전달 규격 | worker 운영과 API 분리, 중단 처리 |
| 환경변수 **이름**, 외부 대상·인증 방식·필요 권한 | 비밀키 주입·외부 통신·오류 진단. 실제 비밀값은 문서에 적지 않음 |
| 공개 입력과 실제 HER2 예측의 단계별 경과시간·CPU·최대 메모리 | 서버 규격·전체 실행 시간·동시 작업 수·대기 정책 |
| 원본·MSA·예측 복수 구조·보고·임시 파일·로그·캐시의 용량 | 디스크·업로드 제한·보관/삭제·백업 대상 |
| 공급자별 요청 수·제한·사용량·실패·timeout·상태 조회 | 비용·재시도 한도·중복 호출 방지 |

다운로드 파일의 bytes와 처리 중 RAM은 다른 측정값이다. 외부 응답 대기가 병목이면 CPU 증설로 줄어든다고 가정하지 않는다. 실제 측정 전 분 단위 응답 목표나 일별 처리량을 쓰지 않는다.

## 6. Docker·AWS 연결 검증

현재 잠정안은 단일 EC2에서 web·api·worker·db를 Docker Compose로 운영하는 것이다. Compose는 시작 순서와 준비 완료가 다르므로 DB healthcheck·마이그레이션·API/worker 시작 조건을 확인해야 한다. [Docker 시작 순서](https://docs.docker.com/compose/how-tos/startup-order/)

Caddy의 일반 도메인 기반 자동 HTTPS 경로에는 DNS·80/443 도달성·쓰기 가능한 영속 데이터 디렉터리 등의 조건이 있다. 도메인·실제 네트워크가 미정이므로 자동 인증서 발급 완료를 전제하지 않는다. [Caddy HTTPS](https://caddyserver.com/docs/automatic-https)

EC2의 중지·시작에는 공인 IPv4 변경 가능성이 있으므로 재시작 후 DNS·접속·TLS·저장 상태를 함께 확인해야 한다. [AWS EC2 중지·시작](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Stop_Start.html)

## 7. 운영 종료 조건과 미정 사항

사용자 답변: **해커톤 결과 발표까지 가동하고 탈락하면 종료, 좋은 성과가 있으면 유지 검토**. 정확한 발표일·종료 시각·예산 상한은 아직 없고 AWS 계정·도메인도 정해지지 않았다. 유지 여부는 후속 결정이며 무기한 운영으로 바꾸지 않는다.

비용 산정에는 호스트 가동·저장·백업·주소·전송·모델 사용 항목을 함께 확인해야 한다. 요율·리전·가동 시간이 정해지지 않았으므로 현재 금액 추정은 하지 않는다. 자원 종료는 DB·구조·결과의 보관·삭제 정책과 함께 계획하며, 종료 계획을 실제 자원 삭제 실행으로 해석하지 않는다.

배포 전 남은 결정은 공개 실행의 이용 조건, 제공자·계정, 임시 결과 접근·삭제 방식, 실제 입력·실행 한도와 D6 실측, 예산·계정·도메인이다. 이 항목이 미정이어도 화면 소비 요구·공개 자료 실험·Docker 의존성 조사는 진행할 수 있다.
